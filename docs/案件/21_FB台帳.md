- 作成日: 2026-09-01
- 目的: **オーナーが実機で使って得た気づき**を一元管理し、今後の開発の入力にする
- 上位文書: [要件定義書](../仕様/12_要件定義書.md) §3（開発の現況）
- 運用ルールをなぜそう定めたかは本書に書かず、`log_21_FB台帳.md` へ日付順に積む（最初のエントリが出た時点で作る）

要求そのもの（F-XXX）は[要件バックログ](./22_要件バックログ.md)、挙動を変えない技術活動は[技術改善バックログ](./23_技術改善バックログ.md)が持つ。**挙動レベルの仕様判断が発生したら、直す前に仕様書群へ反映する**（CLAUDE.md）。

## 運用ルール

**1 エントリ＝ §一覧の 1 行 ＋ §詳細の 1 節。** 片方だけ手で足すと索引と本文が離れるので、`sh scripts/docs-check.sh` が対で持っているかを見る。

§一覧の列は 5 つで、**すべて埋める**。

| 列 | 中身 |
|---|---|
| ID | `FB-XX` |
| 起票日 | オーナーが挙げた日 |
| タイトル | 指摘の名前 |
| 詳細 | `#fb-xx` を指すリンク |
| 状態 | `未対応` ／ `完了 YYYY-MM-DD` ／ `対処不要 YYYY-MM-DD` |

§詳細の節は次の順で書く。**空にする項目は行ごと落とす。**

| 項目 | 中身 |
|---|---|
| 現象 | オーナーの言葉 |
| 調べたこと | 実装や条項を当たって分かった事実。現象を読めば足りるなら落とす |
| 詰める点 | 直す前にオーナーと決めることの一覧。決まったら落とす |
| 決定 | 決まったこととその理由。決まるまでは書かない |
| 裏取り | 外部の出典に当たった記録。当たっていなければ落とす |
| 残したもの | 直したあとに残る不都合や、戻すときの手 |
| 関連 | 一緒に決めたい FB や、反映先の条項 |

- **セル内に `|` を書かない**（`docs-check` が列を数えられなくなる）
- 分類は `### 仕様判断待ち` ／ `### 着手待ち` の 2 つ。**どちらに置くかは「直す前にオーナー判断が要るか」で決める**
- **完了・対処不要にしたエントリは、状態更新と同じコミットで[完了記録](./closed_21_FB台帳.md)へ移す**（`sh scripts/ledger-move.sh FB-XX --status '完了 YYYY-MM-DD'`）

## 詳細

### FB-04

- 現象: 「行き先が存在しない場合に『今日はどこへ？』→『2 件で開始』が少し違和感ある」。行き先を 1 つも作っていないと全件モードになり、問いと答えが噛み合わない
- 詰める点: 全件モードのときだけ見出しを変えるか、別の見せ方にするか
- 関連: [13](../仕様/13_画面定義書.md) 画面 03。**[FB-09](#fb-09) と同じ「03 でどこでも買えるものをどう見せるか」の話なので一緒に決める**

### FB-07

- 現象: 「絞り込みタグの選択状態の視認性が低い」。素の `FilterChip` の選択色（`secondaryContainer` ＝ accent-soft）を使っている。地が 1 段になった（[FB-01](./closed_21_FB台帳.md#fb-01)）ぶん、選択面との差が小さい
- 詰める点: 選択の示し方（枠・濃さ・✓ の付加）
- 関連: [13](../仕様/13_画面定義書.md) 画面 01・§5。**[FB-08](#fb-08) と一緒に決める**

### FB-08

- 現象: 「絞り込みタグが 1 行なのでカテゴリと行き先を排他に選べることが分からない」。チップが 1 行に連なるため群の境が見えず、**各群 0〜1 個ずつ選べる**ことが伝わらない
- 決定: **カテゴリ群と行き先群の間に仕切りを挟む**（オーナー判断 2026-09-01）。行を分けず 1 行のままにするので、横スクロールも 1 本で済む
- 関連: [13](../仕様/13_画面定義書.md) 画面 01。**チップの見た目は [FB-07](#fb-07) と一緒に決める**

### FB-09

- 現象: 「『今日はどこへ？』でどこでも（行き先なし）は一緒に入っていることが＋1 などの暗黙でしか分からない点が少し違和感ある」
- 詰める点: 行に添えるか、注記を置くか、別の見せ方にするか
- 関連: [13](../仕様/13_画面定義書.md) 画面 03。**[FB-04](#fb-04) と一緒に決める**

### FB-10

- 現象: 「気づいたものの検索をかなカナくらいは対応したい。漢字どうするかはまた検討」。画面 05 は「ひらがな・カタカナの同一視はしない」と明記して実装もそのとおり
- 決定: **かな・カナに加えて全角・半角も同一視する**（オーナー判断 2026-09-01）。漢字・読みは別途検討。実装量はほぼ変わらず、「打ち方の揺れで見つからない」がまとめて消える
- 関連: [13](../仕様/13_画面定義書.md) 画面 05。実装は `AddNoticedSheetUiState` の当たり判定 1 か所

### FB-11

- 現象: 「『紐づく n 件は「どこでも買えるもの」になります。』で『どこでも買えるもの』という語彙が出てくるのがここが初になる気がする」。調べると UI での初出は **04 の区切りラベル**（次いで 05 の区切り、09b の削除確認）。加えて**プールのチップだけ「🏬 どこでも」と短い別表記**で、同じ概念が 2 通りで出ている
- 詰める点: 語を揃えるか、どこかで説明を挟むか
- 関連: [13](../仕様/13_画面定義書.md) §3・画面 01・04

### FB-13

- 現象: 「行き先タグだけ絵文字アイコンがあるのが違和感なのでカテゴリにもつけるか検討。良い絵文字が選べるか次第」
- 調べたこと: 🏬 は行き先の**表示のときの前置**で名前の一部ではない（画面 01）。出るのは 3 か所——プールの行の行き先タグ、プールの絞り込みチップ（行き先と「🏬 どこでも」）、05 の「他の行き先から」の行。カテゴリ側は素の名前だけ
- 詰める点: **カテゴリにも付けるか、行き先の 🏬 を外して両方とも素の名前にするか。** 付けるなら候補は 🏷️（分類そのもの。🏬 との対比が「どこで」対「何の」になる）／📁／🔖。**🏷️ は異体字セレクタを持つので Android と iOS で見え方が変わりうる**——決める前に実機で 2 つ並べて見る
- 関連: [13](../仕様/13_画面定義書.md) §3・画面 01・05。**チップ列は [FB-07](#fb-07)（選択状態）・[FB-08](#fb-08)（仕切り）・[FB-11](#fb-11)（どこでもの表記）と同じ場所を触る**ので、まとめて決めると手戻りが少ない
