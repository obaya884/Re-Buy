未実装要求を**決定状態（レーン）＋熟度タグ＋着手トリガ**で管理する。挙動レベルの仕様判断が発生したら**先に**仕様書群へ反映し、本書は一行の要約に留める。

## 書式

**1 エントリ＝レーンの表の 1 行**。列は次の 6 つで、**すべて埋める**。

| 列 | 中身 |
|---|---|
| ID | `F-XXX` / `N-XX` |
| タイトル | 要求の名前 |
| 熟度 | **着手時にオーナーの仕様判断が要るか**を、参照先 docs の実体で判定する（下表）。レーンとは直交する軸 |
| 内容 | 何を作るかの一行要約。無ければ `-` |
| トリガ | **着手条件。ここを空にしない**——トリガの無いエントリは次の選出で永久に拾われない |
| 参照 | 反映先の条項・検討ドキュメント |

### 熟度の判定

| 熟度 | 条件（**参照先を開いて確かめる**） | 着手したらどこから始まるか |
|---|---|---|
| 仕様済 | 画面定義書（＋必要ならデータモデル定義書）に操作仕様の実体がある | 実装 |
| 設計済 | 検討ドキュメントに方式がある。画面への展開はこれから | 画面定義書への展開判断 |
| 列済 | データ列だけ用意済み。UI は白紙 | UI の仕様判断 |
| 未詰め | 要求文しかない | 仕様判断（オーナーとの対話） |
| `-` | 未評価 | 不明。次に触るとき判定する |

- **セル内に `|` を書かない**
- レーンは `確定・着手待ち` / `候補・見極め中` / `監視項目` の 3 つ。**状態は行に持たず、どの表に置くかで表す**
- 見送りの出口: やらないと決めたら憲章 §6 スコープ外＋[憲章の決定ログ](../仕様/log_11_憲章.md)へ落とす
- **完了したエントリは[closed_22_要件バックログ.md](./closed_22_要件バックログ.md)へ移す**。移す際は 1 行を `## F-XXX タイトル（完了日）`＋対応・反映先の節に展開する
