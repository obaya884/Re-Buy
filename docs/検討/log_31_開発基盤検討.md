# 開発基盤検討 決定ログ

- [開発基盤検討](./31_開発基盤検討.md) の「なぜそうしたか」を日付順に積む。本文は現在の仕様だけを持つ

| 日付 | 決定 | 理由 |
|---|---|---|
| 2026-08-29 | spec の置き場所を `docs/superpowers/specs/` ではなく `docs/検討/` にする | ② で導入する hitosuji 流の番号体系と一致させ、後で移す手間を省く |
| 2026-08-29 | ② のタスクを T-XX として台帳 23 に起票して進める | 台帳を「作ってから使う」のではなく最初から回し、`ledger-move` と `docs-check` の実戦にする。hitosuji も T-01（CI）から始まった |
| 2026-08-29 | CI で Android SDK のセットアップを行わない | ubuntu-latest に必要な platform・build-tools がプリインストール済み。ステップを減らして実行時間を抑える |
| 2026-08-29 | CI の verify を build と instrumented の 2 ジョブに最初から分ける | オーナー判断。unit test の結果をエミュレータ起動を待たずに得る。コンパイルの重複より壁時計時間を優先 |
| 2026-08-29 | Dependabot は weekly | 趣味ペースで daily だと PR が溜まる。CI で自動検証されるので週 1 で十分 |
| 2026-08-29 | コード変更の規約は「原則 Edit、機械的な一括置換は例外として許可し直後に `git diff` を提示」とする | 判断を伴う変更は 1 箇所ずつ考えることに意味がある一方、識別子の改名のような機械的置換まで手作業にする理由はない。可視性は直後の diff 提示と PR の diff で担保する |
| 2026-08-29 | インストルメンテーションテストを ② から CI で回し、方式は Gradle Managed Device にする | オーナー判断で CI に含める。GMD なら `./gradlew` の 1 コマンドでローカル・verifier・CI が同じ手順になり、サードパーティの Action に依存しない。ATD イメージは API 31〜36 に存在する（SDK 一覧で確認。公式ドキュメントの「API 30 のみ」は古い） |
| 2026-08-29 | 署名鍵・証明書の操作を settings.json の deny に最初から入れる | オーナー判断。⑤ より前に触れる理由がなく、事故を構造で防ぐ |
