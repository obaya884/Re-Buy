## 1. 出発点 — 基本ループはあるのに毎週使えない理由

オーナーの実感（2026-08-31 のブレストより）。機能の欠落ではなく、ループの体験設計・導線・UI の完成度が問題。

- 下タブでリストと買い物かごを移動するのが違和感。出発前に見る「買い物リスト」タブと買い物タブの情報量がほとんど同じで冗長
- カテゴリ設定や品目追加の導線が弱い。追加操作そのものが重く、カテゴリの位置づけが曖昧
- 全体的に UI が素の Material のままで、情報の見せ方・レイアウトが練れていない
- データ設計・バリデーションがしっかりしていない
- 信頼性・規約画面はいま問題ではない（規約類はリリースまでに作れば良い）

## 2. 構造 — 買い物は「モード」

タブを全廃し、プール画面を唯一の根にしたスタック構成にする。買い物は「開始 → 店でチェック → 終了」という出入りのあるモードとして扱う。

```
プール（根）
 ├─ 登録シート（アプリバーの＋。新規カテゴリ・行き先の作成ダイアログを内包）
 ├─ 品目編集シート（行の長押し）
 ├─ 買い物開始シート ──▶ 買い物モード画面 ──（足すシート）
 └─ 設定 ──▶ カテゴリの管理／行き先の管理／テーマ／ライセンス
```

- 旧「買い物リストタブ」は買い物開始シート（出発前ビュー）に置き換え、確認画面の重複を解消する
- 独立した「品目編集画面」は廃止し、プールが管理画面を兼ねる
- 各画面の見た目と挙動の要点は[画面モック](./guide_33_画面モック.html)（12 フレーム）が正。詳細な文言・状態は画面定義書（13）で確定する。**モックは 13 ができるまでの暫定の正であり、13 の確定時に削除して本項の参照を 13 に書き換える**

## 3. 概念モデル

| 概念 | 内容 |
|---|---|
| 品目 | 名前・カテゴリ 0..1・行き先 0..1・状態（現行 3 状態を維持）・最終購入日。表示順は登録順（古い順）固定 |
| カテゴリ | 品目を区別する自由なタグ。何で区別するかはユーザーに任せる。手動並び順を持つ |
| 行き先 | 買う店。カテゴリとは独立の概念。手動並び順を持つ。品目から見て 0..1（1 つの行き先には複数の品目が紐づく多対一。品目が複数の行き先に属することはできない） |
| どこでも買えるもの | 行き先なし（null）の品目の呼び名。開始シートに独立したグループとしては出さず、すべての行き先のモードに区切り付きで表示される。カゴに行き先付きの品目が 1 件も無いときだけ「n 件で開始」の全件モード（タイトル「買い物中」）になる |
| 買い物モード | 新しいエンティティは作らない。モードの一覧は「選んだ行き先の品目 ∪ どこでも買えるもの」で常に DB から導出できる |

憲章 §4 の旧記述「カテゴリ＝行く場所」は実態とずれていたため、本コミットで憲章を修正した（カテゴリ＝区別タグ、行き先＝別概念）。行き先の必須化は否決（理由は log_33）。

## 4. 画面と挙動の要点

モックのキャプションと合わせて画面定義書（13）の骨子になるもの。

### 操作の共通作法

- 行タップ＝最頻で取り消し可能な操作（プールではカゴ出し入れ、モードではチェック）
- **行の長押し＝編集シート**（プールの品目・カテゴリ管理・行き先管理で共通）。削除は常に編集シートの中に置き、確認ダイアログで影響を件数提示する
- FAB は置かない。品目の登録はアプリバーの＋から

### プール

- カゴ入りは行の色で示し、一覧の上には寄せない（トグルで行が飛ばないように）
- 絞り込みチップはカテゴリ・行き先を各 0〜1 個選べて AND 結合、「すべて」で解除。行き先フィルタは厳密（どこでも買えるものは「🏬 どこでも」チップで絞る）。行き先チップにはシステムが絵文字 🏬 を表示時に前置する（名前の一部ではない）
- 空状態は「まだ何も登録されていません」＋登録への誘導。カゴ 0 件のとき「買い物を始める」は無効

### 登録・編集

- 登録シートは名前だけで確定でき、カテゴリ・行き先はチップで任意選択。「続けて登録」は名前だけクリアしチップ選択を保持する
- 「＋ 新しいカテゴリ／行き先」は名前だけの小ダイアログ。作成で即登録され、チップ列に選択済みで現れる

### 買い物開始シート・買い物モード

- 開始シートはカゴを行き先別に内訳表示（どこでも分は件数の「＋n」のみ、名前プレビューは表示順の先頭 2 件固定）。行タップでその行き先のモードへ。行き先付きが 1 件も無ければ「n 件で開始」の 1 行のみ（モードタイトルは「買い物中」）
- モードの ←・システムバックには終了確認ダイアログ（シート表示中のバックはシートを閉じるだけ）。アプリを閉じてもチェックは DB に残り、プールから再入場すれば続きから。モードでは長押し編集は無効
- 「買い物を終了」でチェック済みだけプールへ戻る（最終購入日を記録）。未チェックはカゴに残る

### 気づいたものを足すシート

- 初期表示は今の行き先＋どこでも買えるものの未追加分。検索は全品目対象で、追加済みは「追加済み」表示（タップ無効）、他の行き先のヒットは別枠に出す
- 他の行き先のヒットのタップは「あの店で買うものを思い出した」——その行き先のカゴに入るだけで今のモードには現れず、スナックバーで通知する
- ヒットが無ければ「この名前で登録する」ボタン（固定文言）でのみ新規登録（行き先＝今の店・即カゴ入り）。キーボードの確定では登録しない
- どの経路も 1 件でシートは自動で閉じる

## 5. 語彙

UI に出す語彙は画面定義書（13）の用語節で固定する。方針:

| 概念 | UI に出す語 | UI に出さない実装語彙 |
|---|---|---|
| 品目 1 つ | 名詞を出さない（動詞・実名・「もの」で語る） | 品目・Item・アイテム |
| 品目を新しく作る | 登録 | insert |
| 買うものに入れる | 追加・追加済み・未追加 | カゴ・basket・InBasket |
| 常駐する全品目の集合 | 名詞を出さない（「全 n 件」） | プール・pool |
| 店でチェックする状態 | 買い物中・チェック | 買い物モード・mode |
| 品目の分類タグ | カテゴリ | Category |
| 買う店 | 行き先 | destination |
| 行き先のない品目 | どこでも買えるもの | 行き先なし・null |

- 「登録＝品目を作る」「追加＝買うものに入れる」の書き分けが鍵。「品目」は仕様・実装の概念語として使い、UI 文言には出さない

## 6. データの規律

データモデル定義書（14）で確定させる内容の方向。

- **バリデーション**: 品目・カテゴリ・行き先の名前に共通で、トリム後の空文字不可・同種内の重複不可・上限文字数（具体値は 12〜14 で確定）。UI で弾き、データ層でも守る二重の網。絵文字を含む入力は禁止しない
- **並び順**: 品目は登録順（古い順）固定。カテゴリ・行き先は並び順の値を持ち管理画面のドラッグで手動並び替え。モード内は「店の品目 → どこでも買えるもの」の順
- **Migration**: 行き先テーブル・並び順の追加でスキーマが変わるが、④ の実装中は[アーキテクチャ定義書](../仕様/15_アーキテクチャ定義書.md) §2.3 のとおり version を上げて入れ直しでよい。**MVP をオーナーの端末に投入して日常利用が始まった後は、スキーマ変更に明示的な Migration とそのテストを必須とする**——15 §2.3 の境界を「⑤ ストア公開」から前倒しした（本コミットで 15 を改定。経緯は log_15）。運用の詳細は 14 に規定する
- カテゴリ・行き先の削除時、紐づく品目は「なし」に戻る（品目は消えない）

## 7. デザイン

- 素の Material から離れ、丸ゴシック見出し＋やわらかい地色＋低彩度アクセントの面構えにする（モックが正）
- 配色は 3 案（若葉・藍・柿）。**テーマ選択は MVP に含め、既定は藍**。明暗（ライト/ダーク）は OS 設定に追従し、選択は端末内に保存
- 通知の作法はスナックバー（画面に変化が見えない操作の完了通知に使う）

## 8. スコープと MVP

- 本書で決めた新構造一式（画面刷新・行き先・どこでも買えるもの・登録/追加の導線・バリデーション・並び順・デザイン刷新・テーマ選択）を F-XXX に分解し、**その全部を MVP とする**
- MVP に入れないもの: 収益（プレミアム・広告。MVP 実装後に検討——憲章 §7）・利用規約/プライバシーポリシー/問い合わせ画面（リリースまでに作る。それまで行ごと出さない）・多言語
- 完了条件はロードマップ ④ のとおり（MVP の F-XXX がすべて closed、オーナーが数週間使い続けている、FB が回っている）
