    - **コードの変更は原則 Edit / Write ツールで行う**。**判断を伴う変更は 1 箇所ずつ Edit する**——どこを直すかを都度考えることに意味があり、まとめて置換すると文脈に応じた直し（周りのコメントの追随など）が抜ける
    - **例外は「意味を変えない機械的な一括置換」**（識別子の改名など）。この場合は python / sed 等を使ってよいが、**実行直後に `git diff` を提示する**——部分一致で意図しない箇所まで変わっていないかをオーナーが見られるようにする（レビューの正は最終的に PR の diff なので、永続する変更の可視性はそちらでも担保される）
    - 変異テスト（コードを壊してテストが落ちるか確かめる）はメインセッションが Edit で 1 か所ずつ行い、verifier には変異後の実行だけを頼む

## 8. CI と Dependabot（F）

`.github/workflows/ci.yml`:
- トリガ: `pull_request` と `push`（main）。`concurrency` で同一 ref の古い実行をキャンセル。`permissions: contents: read`
- `docs` ジョブ: `actions/checkout@v7` → `sh scripts/docs-check.sh`
- `verify` ジョブ: `actions/checkout@v7` → `actions/setup-java@v6`（temurin 21）→ `gradle/actions/setup-gradle@v6`（キャッシュ）→ `./gradlew build` → KVM を有効化（`/dev/kvm` の udev ルール追加。ubuntu-latest はハードウェアアクセラレーション対応）→ `./gradlew pixel6Api35DebugAndroidTest -Pandroid.testoptions.manageddevices.emulator.gpu=swiftshader_indirect`。ubuntu-latest ランナーに `android-37.0` と build-tools 37.0.0 がプリインストールされているため SDK セットアップは不要（2026-08-29 時点の runner-images で確認。将来 compileSdk を上げる時は再確認）
- インストルメンテーションテストは **Gradle Managed Device（GMD）** で回す。`app/build.gradle.kts` の `testOptions.managedDevices.localDevices` に `pixel6Api35`（`device = "Pixel 6"`, `apiLevel = 35`, `systemImageSource = "aosp-atd"`）を定義する。ローカル（Apple Silicon は arm64 イメージ）・verifier・CI（x86_64 イメージ）が同じ 1 コマンドで同じテストを回せる。システムイメージ（`$ANDROID_HOME/system-images/android-35/aosp_atd/x86_64`）は `actions/cache` でキャッシュし、初回以外のダウンロードを省く（効果は実装時に計測し、効かなければ外す）
- `verify` は最初から **`build`（lint・unit test・assemble）と `instrumented`（GMD）の 2 ジョブに分け、並列に回す**。unit test の結果をエミュレータ起動を待たずに得るため。コンパイルは 2 ジョブで重複するが壁時計時間を優先する（オーナー判断 2026-08-29）

`.github/dependabot.yml`:
- `gradle`（version catalog 対応）と `github-actions`。趣味ペースなので **weekly**。minor/patch はグループ化。`open-pull-requests-limit: 5`

## 9. `.claude/settings.json`（G）

- allow: `./gradlew` の各タスク（末尾 `*` は `--tests` や `-P` が要る `testDebugUnitTest` `pixel6Api35DebugAndroidTest` `tasks` だけに付ける。`build *` のような形は `--init-script` で任意コードが通るので付けない）、`Bash(sh scripts/*)`、`Bash(gh pr view*)`・`list`・`diff`・`checks`・`create`、`Bash(gh run view*)`・`list`・`watch`、`Bash(gh repo view*)`、`Bash(android emulator *)`、`Bash(adb devices*)`
- ask: **`git push` はすべて ask**（`-u origin t-*` のような allow は refspec `t-xx:main` で main へ push できてしまう。force-with-lease も同様）、`Bash(gh api repos/*)`（任意の HTTP メソッドが通る）、`Bash(gh pr merge*)`、`Bash(gh repo edit*)`、`Bash(gh release*)`、`Bash(git push origin main*)`
- deny（最初から入れる。署名鍵・証明書は ⑤ より前に触れる理由がない）: `Bash(keytool *)`、`Bash(apksigner *)`、`Bash(jarsigner *)`、`Bash(openssl *)`、`Bash(security *)`（macOS キーチェーン）、`Bash(cat *.jks)`・`*.keystore`・`*.p12`・`*.pfx`・`*.pem`・`*.key`、`Bash(cat keystore.properties)`、`Read(**/*.jks)`・`**/*.keystore`・`**/*.p12`・`**/*.pfx`・`**/*.pem`・`**/*.key`・`**/keystore.properties`

## 10. git 運用（H）

`docs/仕様/16_git運用定義書.md` §1 に書く。要点:
- ルーティング: docs・軽微（typo・文言・挙動に触れない小修正）→ main 直コミット／コード・挙動の変更 → ブランチ → PR → CI 緑 → 動作確認 → 合図で squash マージ／迷ったら PR 側
- ブランチ命名: `<ID>-<slug>`（小文字、`a-z 0-9 -` のみ、スラッシュ不可）。ID は `t-XX`（②〜）、`f-XXX` / `n-XX` / `fb-XX`（④〜）。1 ブランチ = 1 PR、マージ後削除
- ブランチは push 済みの main から切る（squash の性質上、未 push コミットが混ざる事故を防ぐ）
- ② の実装は「ツール整備」なので main 直で進めてよいが、**CI の動作検証のために 1 本だけ PR を通す**（T-XX のどれかを PR にする）
