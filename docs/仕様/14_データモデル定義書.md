## 1. エンティティと関係

```
categories 1 ──── 0..n items n..0 ──── 1 destinations
（カテゴリ 0..1）              （行き先 0..1）
```

- 品目（items）はカテゴリ・行き先をそれぞれ **0 または 1 個**持つ。多対多は作らない
- 買い物モードにエンティティは無い。モードの一覧は「選んだ行き先の品目 ∪ どこでも買えるもの」で常に DB から導出する（§4）
- 行き先が null の品目が「どこでも買えるもの」

## 2. テーブル定義

DB 名は `app_database`（**変えると既存端末のデータを見失う**）。既存の items・categories を拡張し、destinations を新設する。

### items

| 列 | 型 | 制約・既定値 |
|---|---|---|
| id | Int | PK・autoincrement |
| name | String | UNIQUE インデックス。保存時は常にトリム済み |
| status | Int | 0＝常駐・1＝カゴ・2＝チェック済み（§3）。既定 0 |
| categoryId | Int? | FK → categories.id・ON DELETE SET NULL・インデックス |
| destinationId | Int? | FK → destinations.id・ON DELETE SET NULL・インデックス。**新設列** |
| lastBoughtAt | Instant? | 最終購入日時。未購入は null |
| createdAt | Instant | 登録日時 |
| updatedAt | Instant | 更新日時 |

### categories / destinations（同型）

| 列 | 型 | 制約・既定値 |
|---|---|---|
| id | Int | PK・autoincrement |
| name | String | UNIQUE インデックス（同一テーブル内）。保存時は常にトリム済み |
| sortOrder | Int | 手動並び順。**新設列**（destinations はテーブルごと新設） |
| createdAt | Instant | 作成日時 |
| updatedAt | Instant | 更新日時 |

## 3. 状態モデル

品目の状態は現行の 3 値を維持する（DB 上の値 0・1・2 も変えない）。

| 値 | 状態 | UI での見え方 |
|---|---|---|
| 0 | 常駐（カゴ外） | プールで未追加 |
| 1 | カゴ入り・未チェック | プールで追加済み。モードで未チェック |
| 2 | カゴ入り・チェック済み | プールで追加済み。モードで ✓ |

**遷移**（起こす操作はすべて[13](./13_画面定義書.md)の画面で定義済み）:

| 遷移 | 操作 |
|---|---|
| 0 → 1 | プールの行タップ（カゴ入れ）、05 での追加・新規登録 |
| 1 → 0 | プールの行タップ（カゴ出し） |
| 2 → 0 | プールの行タップ（カゴ出し。チェックは失われる） |
| 1 → 2 | モードの行タップ（チェック） |
| 2 → 1 | モードの行タップ（チェック外し） |
| 2 → 0 ＋ lastBoughtAt 記録 | 「買い物を終了する」。一覧の状態 2 全件に対して一括で行い、lastBoughtAt は終了時刻 |

モードからの離脱・アプリ終了は状態を変えない（チェックは DB に残り、再入場で続きから）。

## 4. 導出（クエリ仕様）

画面の一覧はすべて以下の導出で得る。「登録順」＝ id 昇順。

| 画面 | 導出 |
|---|---|
| 01 一覧 | 全品目を id 昇順。カテゴリ絞り込みは categoryId 一致、行き先絞り込みは destinationId 一致（「どこでも」は IS NULL）、両方指定は AND |
| 01 バッジ・03 の件数 | status が 1 または 2 の品目（＝カゴ）を数える |
| 03 内訳 | カゴ内に品目を持つ行き先を sortOrder 昇順で。各行の n＝その行き先のカゴ内件数、プレビュー＝同 id 昇順の先頭 2 件の名前、m＝destinationId IS NULL のカゴ内件数 |
| 03 全件モード判定 | カゴが 1 件以上あり、かつカゴ内の全品目が destinationId IS NULL |
| 04 一覧 | カゴ内で「destinationId ＝ 選んだ行き先」を id 昇順 → 「destinationId IS NULL」を id 昇順。全件モードはカゴ全件を id 昇順 |
| 04 進捗 | x＝一覧中の状態 2 の件数、n＝一覧の総数 |
| 05 初期表示 | 状態 0 で「destinationId ＝ 今の行き先 または IS NULL」を id 昇順（全件モードは状態 0 の全品目） |
| 05 検索 | 全品目からトリムした入力の単純部分一致（`name LIKE '%入力%'`）。ひらがな・カタカナの同一視はしない。セクション分けは 13 の 05 |

## 5. バリデーション

品目・カテゴリ・行き先の名前に共通。**UI とデータ層の二重の網**で守る。

| 規則 | 内容 |
|---|---|
| トリム | 確定時に前後の空白（全角含む）を除去し、トリム後の値を保存する |
| 空不可 | トリム後に空文字なら拒否 |
| 重複不可 | 同種内でトリム後の完全一致が既にあれば拒否（更新時は自分自身を除く）。大文字小文字・ひらがなカタカナ等の正規化はしない |
| 上限 | 30 文字。長さは Kotlin の `String.length`（UTF-16 単位）で数え、絵文字が 2 文字ぶんに数えられることは許容する |
| 文字種 | 制限しない（絵文字も可）。システムが名前に何かを足すことはない（01 の 🏬 は表示時の前置） |

- **UI の網**: 31 文字目以降は入力できない。確定操作時に検証し、エラーは入力欄の下（文言は [13](./13_画面定義書.md) §2）
- **データ層の網**: Repository が保存前にトリムと全規則の検証を行い、違反は結果型で返す。DB の UNIQUE インデックスが最後の砦

## 6. 並び順

| 対象 | 規則 |
|---|---|
| 品目 | 登録順（id 昇順）固定。並び替え UI は持たない |
| カテゴリ・行き先 | sortOrder 昇順。新規作成は末尾（既存最大値＋1、空なら 1）。管理画面のドラッグで並び替え、確定のたびに保存する。sortOrder の振り直し方は実装に任せる |

## 7. 削除

- カテゴリ・行き先の削除: 紐づく品目の categoryId／destinationId は SET NULL で「なし」に戻る。**品目は消えない**
- 品目の削除: 物理削除。復元は無い（確認ダイアログの文言は 13 の 06）

## 8. Migration 運用

[アーキテクチャ定義書](./15_アーキテクチャ定義書.md) §2.3 の境界に従う。

- **④ の実装中**（MVP 投入前）: destinationId・sortOrder・UNIQUE インデックス・destinations の追加はスキーマ version を上げて**入れ直し**でよい。Migration は書かない
- **MVP 投入後**（オーナーの日常利用開始後）: スキーマ変更には明示的な Migration とそのテストを必須とする。既存列・既存値（状態 0/1/2、DB 名）は本書の定義を保つ

## 9. DB の外に置く設定値

- テーマ選択（若葉・藍・柿。既定は藍）: Room ではなく端末内のキーバリュー保存。保存機構の選定は実装計画で決める
