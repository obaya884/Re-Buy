# 憲章 決定ログ

- [憲章](./11_憲章.md) の「なぜそうしたか」を日付順に積む。本文は現在の仕様だけを持つ

| 日付 | 決定 | 理由 |
|---|---|---|
| 2026-08-29 | 対象ユーザーを「一人で買い物する人」に絞り、共有・同期を対象外にする | オーナー自身の問題がそこにあり、サーバーなしで成立させられる。共有世帯は競合が強く、開発・運用コストが段違いに上がる |
| 2026-08-29 | 「腰を軽くする」（C-2）を C-1 とは独立した価値として置く | 既存アプリとの差はむしろここにある。入力の手間だけなら候補補完でも解決するが、「やること・行く場所が決まっている状態を作る」は設計思想の違い |
| 2026-08-29 | 収益モデルを「無料＋広告、サブスクでプレミアム解除」とし、初回は課金なし | オーナー判断。買い切りも検討したが、まずこの仮説で始め、サブスクの継続価値を説明できなければ切り替える |
| 2026-08-29 | 収益を成功基準に含めない | 成功基準は「自分が使い続ける」「他人が使っている」の 2 つで足りる。収益は目標として ⑤ で追う |
| 2026-08-29 | 初回は日本語のみ | スーパー・薬局という生活文脈が日本の一人暮らしに密着している。多言語化は候補として残す |
| 2026-08-29 | 仮称を FavBasket から Re-Buy に変更 | コンセプト（くりかえし買う）を名前で表す。正式名称は ⑤ |
| 2026-08-29 | applicationId は当面 io.github.obaya884.rebuy とし、逆ドメイン部分は ⑤ の前に再検討する | 公開後は変更できないが未公開の今は無料で変えられる。applicationId は製品名と一致させる必要がなく、開発者としてどの識別子を使うかの判断を公開前まで持ち越す |
| 2026-08-29 | 公開済みコミット履歴の author に載った個人メールアドレスは書き換えず受け入れ、到達手段の例外として §10 に明記する | 資格情報ではなく OSS では一般的。履歴の書き換えは公開直後なら安価だがオーナー判断で見送り、ルールと実態の乖離を文書側で解消する |
| 2026-08-29 | C-5 が揃えるのは機能であって見た目ではないと明記し、iOS の外枠をネイティブ（SwiftUI）で持つ方針を §8 に加える | オーナー判断。③ で Compose Multiplatform を採ると iOS も Material 3 のままになり、iOS 26 の Liquid Glass はシステムが SwiftUI の TabView / NavigationStack に描くため適用されない。C-5 を「見た目まで同一」と読むと各 OS で最適な体験を出す道が塞がれる |
| 2026-08-29 | 最低 iOS バージョンを 26 にする | オーナー判断。Liquid Glass 前提で設計でき、それ以前の見た目を確認する手間が要らない。到達範囲は狭まるが ⑤ のリリースまで時間がある |
