# 画面定義書 決定ログ

- [画面定義書](./13_画面定義書.md) の「なぜそうしたか」を日付順に積む。本文は現在の仕様だけを持つ

| 日付 | 決定 | 理由 |
|---|---|---|
| 2026-09-01 | 上限超えのエラーにも文言を置き（「30 文字以内で入力してください」）、**起きない想定のエラーにも文言を持たせる**規則にする | F-003 の実装で、打ち切りがあるので上限超えは UI から届かないと判断し、文言を置かずに確定だけ受け付けない形にした。しかしその経路に届くと**赤枠だけが出て理由が分からない**状態になり、§2 の「エラーは入力欄の下に赤字で出す」とも食い違う。オーナー判断で、今後のエラーも含めて文言を必ず持たせることにした |
| 2026-09-01 | 同梱するフォントは丸ゴシック（Zen Maru Gothic）の Bold 1 ウェイトだけにし、本文は OS 既定に任せる | 日本語フォントは 1 ウェイトで約 3.8MB あり、2 書体を同梱するとアプリの配布サイズが数倍になる。オーナー判断で「見出し・CTA だけ同梱」を選んだ——丸ゴシックは目に付く場所に効き、本文は OS 既定でも日本語として自然に読める。ライセンス（OFL-1.1）は `configPath` で一覧に手足しした |
| 2026-09-01 | 絞り込みチップは選択中にもう一度タップすると個別に解除する。行き先が無い品目の行には「どこでも」タグを出さない | F-005 の実装中に、画面 01 の記述では決まらない 2 点として挙がった（仕様レビューが検出）。前者はチップ UI の一般的な挙動で、片方だけ外すのに「すべて」から選び直す手間が要らない。後者はカテゴリが無いときにタグを出さないのと対称で、行き先が付いているものだけが目立つほうが一覧として読みやすい。**どちらもオーナー判断** |
| 2026-09-01 | 画面 07 のバージョンは**画面の下端に固定**する（行の最後ではなく） | F-011 の仕様レビューが「『最下部に』は行の末尾とも画面の下端とも読める」と指摘した。**オーナー判断**。行が少ないうちは下に空きが出るが、行が増えても位置が変わらないほうが、探しに来たときに見つけやすい |
| 2026-09-01 | 画面 05 の「他の行き先から」の行に行き先名を添える | F-010 の着手時に、05 の記述では決まらなかった。**オーナー判断**。このセクションだけは複数の店の品目が混ざるので、名前だけだとタップ後にどこのカゴへ入ったかが分からない。タップ後のスナックバー（「◯◯に追加しました」）だけでは、押す前に選べない |
| 2026-09-01 | 画面 04 の「買い物を終了する」は、チェック済みが 0 件でも押せる。終了時に待ち時間やスピナーは置かない | F-009 の着手時に、どちらも 04 の記述では決まらなかった。**オーナー判断**。前者は「何も買わずに帰る」も買い物の終わり方で、無効化すると ← の離脱確認しか戻る道が無くなるため。後者は旧画面が 500ms 待ってスピナーを出していた（技術改善バックログ T-27）が、確認ダイアログが無くなった 04 では**押した結果が一覧の消失として即見える**ので、待たせる理由がない |
| 2026-09-01 | チップの解除作法は画面 01 だけでなく §2（操作の共通作法）に置く | F-006 で登録シートの選択チップにも同じ作法を入れたところ、仕様レビューが「02 には書かれていない」と指摘した。**同じ操作が画面ごとに違うほうが驚く**ので、規則を上位へ 1 か所にまとめ、01 の記述は参照に変えた |
