## 1. テストの段

| 段 | 置き場所 | 対象 | 実行 | 走る場所 |
|---|---|---|---|---|
| ホスト（共通） | `shared/*/src/commonTest` | プラットフォームに依らない純粋ロジック（コンバータ・UiState の派生値・Repository の遷移規則・`Navigator`） | `testAndroidHostTest` ／ `iosSimulatorArm64Test` | **Android と iOS の両方** |
| ホスト（プラットフォーム別） | `shared/*/src/androidHostTest` `src/iosTest` | 片方でしか書けないもの（`kotlin-reflect` を要するもの・日付書式の実測値・native にしか無い `Room.inMemoryDatabaseBuilder`） | 同上 | 片方だけ |
| 画面（iOS） | `shared/ui/src/iosTest` | `runComposeUiTest` で `ReBuyApp()` を描いて操作する（画面遷移・戻る・シート） | `iosSimulatorArm64Test` | iOS のみ |
| インストルメンテーション | `androidApp/src/androidTest` | Room（マイグレーション・DAO）・Compose UI・リソースが APK に載っているか・プロセス death からの復元 | `pixel6Api35DebugAndroidTest`（GMD） | Android のみ |

**既定は `commonTest`。** 片方でしか書けない理由があるときだけ分ける。

**画面を動かすテストは `commonTest` に置けない。** 置くと Android 向けにもコンパイルされ、Android フレームワークの無い素の JVM（`testAndroidHostTest`）で実行されて `android.os.Build.FINGERPRINT` が null で落ちる。Robolectric が要るが、その有効化は `@RunWith` という JUnit 4 のアノテーションなので `commonTest` には書けない。Gradle 側で除外する手もあるが、**除外がソースから見えずクラス名の一致で効く**ので採らない（[§4](#4-テストが-0-件で緑になるのを止める) と同じ「黙って外れる」形になる）。Android 側は instrumented が実物の `MainActivity` を起動して同じ経路を見ている。

## 2. 原則

### 2.1 期待値をリソースから引かない

文言や書式を固定するテストは、**期待値をリテラルで書く**。`Res.string.*` や `DateTimeFormatter` から期待値を作ると自己参照になり、値が壊れても画面とテストが同じ壊れた値を見て素通りする。

**逆に、キーで引いた先に物があるかを見るテストは実装側の定数を参照する**（`LicenseLibrariesTest` の `ABOUT_LIBRARIES_PATH`）。パスをテスト側に書き写すと、書き写しどうしが一致するだけで実装の誤りを止められない。

### 2.2 網を張ったら変異で確かめる

**テストを足したら、守るはずの箇所を 1 か所ずつ壊して、狙った件だけが落ちることを確認する。** 変異はメインセッションが `Edit` で行い、git で退避しない。段 3 では素朴な実装が変異をすり抜けた例が複数ある（T-32 は 2 回）。

### 2.3 期待件数を書かない

「このモジュールは N 件」と書くと、今度はその数字の更新漏れが起きる。**件数で見るのは「0 件かどうか」だけ**（[§4](#4-テストが-0-件で緑になるのを止める)）。下限を置く場合も、依存の増減で上下しない水準に取る。

### 2.4 プラットフォーム差は両方で見る

`commonTest` に置けば両方で走る。**片方でしか走らないテストは、そのプラットフォーム固有の壊れ方しか止められない**——iOS だけで落ちる不具合（[アーキテクチャ定義書](./15_アーキテクチャ定義書.md) §4.2 の `when` の件）は Android の全テストが緑のまま通り抜けた。

## 4. テストが 0 件で緑になるのを止める

KMP ライブラリプラグインはホストテストが既定で無効で、開け忘れると **0 件のまま緑**になる。convention plugin `rebuy.android.base` の `failOnZeroTests()` が、**テストソースを持つ source set のうち 1 つでも「1 件も実行していない」なら落とす**。

見ているのは `testAndroidHostTest`（`commonTest` ＋ `androidHostTest`）と `iosSimulatorArm64Test`（`commonTest` ＋ `iosTest`）の 2 タスク。JUnit XML の `testsuite name` の単純クラス名と、source set 配下の `.kt` のファイル名を突き合わせる。

設計はすべて実測で決まっており、**どれを外しても止まらなくなる**。

- **テストタスクの `doLast` に置かない。** source set が外れると `NO-SOURCE` でタスクごと飛び、`doLast` も走らない
- **`finalizedBy` に加えて `check` にも繋ぐ。** `finalizedBy` だけだと、`withHostTest {}` の入れ忘れでテストタスク自体が生成されないときに検査ごと消える
- **タスクごとに自分の出力だけを見る。** `build/test-results` を丸ごと数えると、別のタスクが前に残した XML で通る
- **source set 単位で見る。** タスク単位の合計だと、`commonTest` の 106 件が丸ごと消えても `androidHostTest` の数件で緑になる
- **`skipped` を差し引く。** `tests` は `@Ignore` も数えるので、全件 `@Ignore` でも通ってしまう
- **iOS は macOS のときだけ見る。** Linux では Kotlin/Native のテストタスクが無効化されるので、検査だけが走って 0 件と判定してしまう。つまり **iOS 側の 0 件を守っているのは macOS の `ios` ジョブ 1 本だけ**

## 5. CI

| ジョブ | 走る場所 | 中身 |
|---|---|---|
| `docs` | Linux | `sh scripts/docs-check.sh` |
| `build` | Linux | `./gradlew build`（lint・ホストテスト・assemble）＋ `git diff --exit-code`（生成物の鮮度） |
| `instrumented` | Linux | GMD でインストルメンテーションテスト |
| `ios` | macOS | `iosSimulatorArm64Test` ＋ `xcodebuild`（Swift 側とフレームワークのリンク） |

**Linux は iOS のタスクを落とすのではなく「このホストでは走らない」と警告して素通りする。** `ios` ジョブが無いと iOS のコンパイルエラーが CI をすり抜ける。

`ios` のテストとアプリビルドは Kotlin/Native のコンパイルを共有しているのでジョブを分けない（分けると実時間は 1 分縮むだけでランナー消費が 55% 増える）。代わりにアプリビルドを `if: !cancelled()` で常に走らせ、1 回の実行で Kotlin 側と Swift 側の両方の結果が出るようにしている。
