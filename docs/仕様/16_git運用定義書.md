## 1. git 運用ルール

### 1.1 リスク別ルーティング

変更の種類で入口を分ける。判断に迷ったらリスクの高い側（ブランチ＋PR）に倒す。

| 変更の種類 | 経路 |
|---|---|
| docs・軽微（typo・文言・挙動に触れない小修正）・ツール整備 | `main` 直コミット。push はオーナーの合図でまとめて行ってよい |
| コード・挙動の変更 | ブランチ → PR → CI 緑 → オーナー動作確認 → **合図で squash マージ** |

未リリースの間は push ＝ デプロイではない。ストア公開後（ロードマップ ⑤）にリリースブランチの扱いを本書へ足す。

### 1.2 ブランチ命名

- **`<id>-<slug>`**。すべて小文字、使える文字は `a-z 0-9 -` のみ。スラッシュは使わない
- `id` は台帳の ID をそのまま小文字にしたもの: `t-XX`（技術改善バックログ 23）、`f-XXX` / `n-XX`（要求。④ 以降）、`fb-XX`（ユーザーフィードバック 21。④ 以降）。ID の無い作業は先に台帳へ起票する
- **1 ブランチ＝1 PR。ブランチは使い回さない**。マージ時にリモートブランチは自動削除される（リポジトリ設定）。ローカルは squash のためマージ検出できないので、マージ済みを確認のうえ `git branch -D` で消す
- **ブランチは push 済みの main から切る**。squash は派生元からの全差分を 1 コミットに畳むので、未 push のコミットが main に残ったまま切るとその内容まで PR に取り込まれる。切る前に `git status -sb` で ahead が無いことを見る
- `dependabot/*` ブランチはこの命名の対象外

### 1.3 マージ規律

- **push・マージは常にオーナーの合図が前提**。自動マージ・ブランチ保護は設けない
- マージ方式は squash のみ（merge commit / rebase はリポジトリ設定で無効）
- CI（`docs` と `verify`）が緑でないものはマージしない
