# テスト戦略定義書 決定ログ

- [テスト戦略定義書](./17_テスト戦略定義書.md) の「なぜそうしたか」を日付順に積む。本文は現在の仕様だけを持つ

| 日付 | 決定 | 理由 |
|---|---|---|
| 2026-09-02 | `scripts/` の検査は既定では網を持たないが、署名検査だけ段を立てる | 「検査の検査はキリが無い」という判断（2026-09-01）で、スクリプトのテストはその場の確認に使って捨てる運用にしていた。署名検査だけ改めたのは、正規表現が 9 巡のレビューで育つ過程で**3 巡続けて「網を広げた変更がそれ自身で新しい穴を作る」**事故が起きたため（[log_23](../案件/log_23_技術改善バックログ.md) 2026-09-02）。正常系はリポジトリの現状そのものなので、1 語落ちても緑のまま——人手の確認が続かない規模になった時点で前提が変わった |
| 2026-09-02 | §6「いま網が無いところ」には `scripts/` を載せない | §6 は**製品挙動**に対する自動テストの欠落を列挙する節。`scripts/` に網が無いことは[技術改善バックログ](../案件/23_技術改善バックログ.md)の種別表と CLAUDE.md「起動の契機」が一般原則として既に持っており、二重に書くと片方が古くなる |
| 2026-09-06 | **リテラルの対応表を持つ実装は、分岐ではなく表の全域を通す**。あわせて、両辺を同じ実装で畳んで比べる関数には**正規形を実値で固定する網**を別に置く | FB-10 の `SearchKey` で実際に踏んだ。変異で `when` の枝はすべて落ちることを確かめて「網羅した」と判断したが、レビューの実測で**対応表 63 文字のうち 21 文字しか通っていない**と分かった。表の 1 文字を書き換える変異も、表を丸ごと 1 つずらす変異も、残り 42 文字の側では落ちない。分岐網羅は表の中身を何も守らない。直したあとは同じ変異が 3 件・7 件と落ちる。もう 1 つは**偽陽性の構造**——`of(a) == of(b)` の形だけだと、Android と iOS で畳み方がずれても両辺が同じ方向にずれて緑のままになる。実値を固定する網（`assertEquals("あいてむa", …)`）を置いて初めて、プラットフォーム差が失敗として現れる。**算術で畳む枝（全角英数の `- 0xFEE0`）は両端だけでよい**——表とは守り方が違うので、17 §3 に切り分けを書いた |
| 2026-09-06 | **実行時の不変条件チェックをテストの網の代わりにしない。** 表の長さや対応の整合は `init` の `require` ではなくテストで守る | 同じ `SearchKey` で、対応表の不変条件を `object` の `init` に置いて一度は通した。落とした理由は 3 つ。**(1) 捕まえる範囲が狭い**——長さが変わる変異にしか反応せず、1 文字の書き換えや表の回転には無反応で、そこを実際に張っているのは全域往復のテストのほう。**(2) 失敗が読めない**——`ExceptionInInitializerError` で 42 件が一斉に落ち、どのテストも原因を名前で語らない。落とした本人には分かるが、CI のログだけ見る側には読めない。**(3) 発現点が利用者側にずれる**——Kotlin の `object` は遅延初期化なので、発火するのは起動時ではなく「05 で 1 文字打った瞬間」。開発時のミスが「テストが赤」ではなく「端末でクラッシュ」になる。落としたあとで同じ変異を測ると、名前のあるテストが 9 件落ちる |
| 2026-09-06 | **往復して元に戻る変換は、観測できる経路まで含めて通す。** 「範囲を狭めても結果が変わらない」枝は、分岐を通しただけでは網にならない | `SearchKey` の「ひらがな→カタカナ」で踏んだ。カタカナ側は対応表の全域を往復させて塞いだのに、**ひらがな側は範囲を狭める変異が 4 通りとも素通り**していた（レビューの実測）。この枝は最後に `toHiragana` で戻るので、**合成を経由しない限り恒等変換**——観測できるのは「濁点を後置したとき」だけで、そこを通していたのは `か` と `は` の 2 文字しかなかった。濁音 23 組・半濁音 5 組をひらがな側からも全域で通す形にして、同じ変異が落ちるようにした。**「分岐は通った」と「効果が観測された」は別**という一般則として書き留める |
| 2026-09-08 | iOS の端末の戻りは **`NavigationEventInput` を自分で足して流し込む**形で網を張る | FB-18。`runComposeUiTest` は Compose のセマンティクスを中から叩くもので、UIKit の端スワイプを起こせない。ただし `NavigationEventInput` は公開の抽象クラスで `dispatchOnBackCompleted()` を持つので、**実物の端スワイプと同じ経路へ流し込める**。**流す前に同期を挟むこと**——ハンドラの有効・無効は `SideEffect` で押し込まれるので、composition の直後に流すと古い値のまま扱われ、**有効なのに配られない／無効なのに配られる**という逆の結果が出る（両方を実測した。上流の KDoc も "Timing Consideration" として同じことを書いている）。**変異で効きを測ったところ、`enabled` の結線をアプリ全体を通すテストでは守れないと分かった**——配る側は「最後に登録された、有効なハンドラ」を選ぶので、シートが開いていればそちらが先に取り、`isBackEnabled = true` に固定しても緑のまま。**`actual` を単体で描くテストを別に立てて塞いだ**。**当初これを「シートが overlay として登録されるため」と書いたが、裏取りすると誤りだった**——`PRIORITY_OVERLAY` は使われておらず、同じ優先度内の登録順の話。**「`NavDisplay` より内側だから先に受ける」と同じ 1 つの規則**で、説明を 2 つ持つ必要も無かった |
