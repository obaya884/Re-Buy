# テスト戦略定義書 決定ログ

- [テスト戦略定義書](./17_テスト戦略定義書.md) の「なぜそうしたか」を日付順に積む。本文は現在の仕様だけを持つ

| 日付 | 決定 | 理由 |
|---|---|---|
| 2026-09-02 | `scripts/` の検査は既定では網を持たないが、署名検査だけ段を立てる | 「検査の検査はキリが無い」という判断（2026-09-01）で、スクリプトのテストはその場の確認に使って捨てる運用にしていた。署名検査だけ改めたのは、正規表現が 9 巡のレビューで育つ過程で**3 巡続けて「網を広げた変更がそれ自身で新しい穴を作る」**事故が起きたため（[log_23](../案件/log_23_技術改善バックログ.md) 2026-09-02）。正常系はリポジトリの現状そのものなので、1 語落ちても緑のまま——人手の確認が続かない規模になった時点で前提が変わった |
| 2026-09-02 | §6「いま網が無いところ」には `scripts/` を載せない | §6 は**製品挙動**に対する自動テストの欠落を列挙する節。`scripts/` に網が無いことは[技術改善バックログ](../案件/23_技術改善バックログ.md)の種別表と CLAUDE.md「起動の契機」が一般原則として既に持っており、二重に書くと片方が古くなる |
