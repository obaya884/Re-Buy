# アーキテクチャ定義書 決定ログ

- [アーキテクチャ定義書](./15_アーキテクチャ定義書.md) の「なぜそうしたか」を日付順に積む。本文は現在の仕様だけを持つ

| 日付 | 決定 | 理由 |
|---|---|---|
| 2026-08-31 | §2.3 の「Migration を書かない」期間の境界を「⑤ でストアに出すまで」から「④ の MVP 投入（オーナーが日常利用を始める）まで」に前倒しする | ④ の完了条件が「オーナーが数週間使い続けている」になり、守るべき実データが ⑤ より前に生まれる。元の規定の原則（実データの有無を基準にする）は維持し、境界だけを実態に合わせた。④ の実装中のスキーマ変更（行き先テーブル追加など）は従来どおり version を上げて入れ直す。機能・UX 見直し検討 §6 |
| 2026-09-01 | 名前が弾かれた理由（`nameError`）は `uiState` に畳まず、ViewModel が別の `StateFlow` で公開する | 確定のたびに更新される一過性の状態で、入力欄の下にしか出ない。画面の状態として持ち回るより、出す場所の近くで完結させたほうが読みやすい。`uiState` に畳む idiom からの明示的な例外なので、次の画面（行き先の管理）でも同じ形にする |
| 2026-09-01 | DB の外に置く設定値は DataStore ではなく、`SettingsStore` インターフェース＋プラットフォーム実装（`SharedPreferences` / `NSUserDefaults`）で持つ | 置くのはテーマ 1 件で、関連も履歴も要らない。DataStore は依存が増えるわりに、この規模では観測（Flow）以外の利得が無く、観測は `ThemeRepository` の `StateFlow` で足りる。**`expect class` にしなかった**のは、`commonTest` から実体を作れず上の層のテストが書けなくなるため（インターフェースなら fake を差せる） |
