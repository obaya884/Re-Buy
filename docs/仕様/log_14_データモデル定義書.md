# データモデル定義書の決定ログ

[データモデル定義書](./14_データモデル定義書.md)の「なぜそうしたか」を日付順に積む。本文は現在の仕様だけを持つ。

## 2026-09-03 スキーマ version を 1 に畳んだ（T-51）

**決定**: `AppDatabase` の version を 3 から 1 に戻し、`shared/data/schemas/` の 1・2・3 を消して 1 だけを出し直した。**オーナーの端末にあった DB は開けなくなるので、入れ直してもらった。**

**理由**: ④ の実装中は「version を上げて入れ直す」で進めたので、1→2→3 のどの区間にも Migration が無い。この状態のまま 3 を出荷の起点にすると、「1・2 の DB は永久に開けない」という但し書きを §8 が抱え続けることになる。まだ守るべき実データが端末に無いうちなら、畳んでしまえば以後の Migration が 1→2 から素直に並ぶ。

**引き換えに捨てたもの**: 畳んだ時点で端末に入っていた品目・カテゴリ・行き先。version が下がる向きになるうえ `fallbackToDestructiveMigration` も同時に外したので、アプリを消さずに入れ替えると起動時に落ちる。**これができるのは今回が最後**——以後は Migration を書く。

**先に見たもの**: この判断は「実データがまだ無い」に全面的に乗っている。FB の 1 巡目（2026-09-01）は済んでいたが、日常利用としての蓄積はまだ始まっていなかった。
