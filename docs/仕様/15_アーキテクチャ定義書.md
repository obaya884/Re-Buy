## 1. レイヤ構成

UI (Compose) → ViewModel → Repository → DAO → Room の単方向。DI は Koin。

| Gradle モジュール | package | 持つもの |
|---|---|---|
| `:androidApp` | `io.github.obaya884.rebuy` | Android の入れ物（`Application` / `MainActivity`）と instrumented テスト |
| `iosApp/` | — | iOS の入れ物（Xcode プロジェクト、SwiftUI 2 ファイル） |
| `:shared:ui` | `...rebuy.ui` | 画面・ViewModel・ナビ・テーマ・リソース |
| `:shared:domain` | `...rebuy.domain` | Repository |
| `:shared:data` | `...rebuy.data` | Room（エンティティ・DAO・コンバータ） |

依存の向きは `:androidApp` / `iosApp` → `:shared:ui` → `:shared:domain` → `:shared:data`。**Gradle のパスにある `shared` は入れ物を示す語なので package にも namespace にも入れない。**

**iOS の外枠は SwiftUI で持つと決まっている**（[要求定義書](./11_要求定義書.md) §9）が、**まだ実装していない**——現在は `ReBuyViewController` が全画面を Compose 1 枚で描いている。置き換えは [技術改善バックログ](../案件/23_技術改善バックログ.md) の T-44（③ 段 4）。

### 1.1 source set

`:shared:*` の 3 モジュールは KMP。**既定の置き場所は `commonMain`** で、`androidMain` / `iosMain` に置くのはプラットフォーム API を直に触るものだけ。

現在 `commonMain` の外にあるのは次の 4 つだけ。

| 置き場所 | もの | 理由 |
|---|---|---|
| `shared/ui/src/androidMain` `iosMain` | `formatShortDate` の `actual` | 日付の書式は各プラットフォームの慣習に委ねる |
| `shared/data/src/androidMain` `iosMain` | `platformDataModule` の `actual` | DB のパス解決（`Context` ／ `NSDocumentDirectory`） |
| `shared/ui/src/iosMain` | `ReBuyViewController` `setupKoin` | Swift から呼ぶ入口 |

**プラットフォーム差は `expect/actual` で最小の単位に閉じ込める。** 画面ごと分けると共通部分が二重になり、片方だけ直す事故が起きる（instrumented は Android しか見ない）。

## 2. データ層（`:shared:data`）

### 2.1 エンティティと保存形式

- `AppDatabase`: Room。エンティティは `Item` と `Category` の 2 つ。`exportSchema = true` で `shared/data/schemas/` に JSON を出力する
- `Item.categoryId` → `Category.id` の外部キー（`onDelete = SET_NULL`）。JOIN 済みの読み出しは `ItemWithCategory`（`@Embedded` ＋ `@Relation`）を使う
- 日時は `kotlin.time.Instant` で保持し、`InstantConverter` がエポックミリ秒（`INTEGER`）として保存する。ミリ秒未満は切り捨てる（0 方向ではなく過去方向）
- **日時をテキストで保存しない。** 文字列にするとタイムゾーン・ゼロ埋め・存在しない日付の解決規則といった解釈の余地が保存形式に入り込む。エポックミリ秒なら読み方が 1 通りしかなく、壊れた値を別の日時として読む経路が消える
- `ItemStatus` は `NO_DEAL(0)` / `IN_SHOPPING_LIST(1)` / `CHECKED_IN_SHOPPING_LIST(2)` の 3 状態。`ItemStatusConverter` で Int に変換して保存するため、**enum の `value` は既存 DB と互換を壊さない限り変更しない**
- DAO の更新系クエリは `updatedAt = Clock.System.now()` をデフォルト引数で受け取り、更新のたびにタイムスタンプを書き換える

### 2.2 DB の開き方

`BundledSQLiteDriver` ＋ **絶対パス**で開く。パスの解決だけが `expect/actual`。

- Android: `context.getDatabasePath(APP_DATABASE_NAME).absolutePath`。**`getDatabasePath()` は `databases/` ディレクトリが無ければ作る**——同梱 driver は親ディレクトリを作らないので、`File(context.dataDir, "databases/…")` のように「単純化」すると初回起動が壊れる
- iOS: `NSDocumentDirectory` の下。バックアップ対象で、アプリを消すまで残る

`setDriver` と `setQueryCoroutineContext(Dispatchers.IO)` は対で指定する。**Native では `Dispatchers.IO` が `Dispatchers` のメンバではなく拡張プロパティなので、`import kotlinx.coroutines.IO` が別途要る**（無いと「internal で触れない」というエラーになり、版のせいだと誤診しやすい）。

単一性は Koin の `single` が保証する。`@Volatile` ＋ `synchronized` の `INSTANCE` キャッシュは持たない（`synchronized` は JVM 専用で `commonMain` に置けない）。

### 2.3 スキーマ変更時の手順

`AppDatabase` の `version` を上げ、`Migration` を追加し、`RoomMigrationTest.ALL_MIGRATIONS` に登録する。`shared/data/schemas/` に生成された新しい JSON もコミットすること（instrumented テストはこのディレクトリを assets として参照している）。

**オーナーが MVP の日常利用を始める（④ の MVP 投入）までは `Migration` を書かない。** `version` を上げるだけにして、旧 DB を持つ端末は入れ直す。守るべき実データがまだ無い段階で移行コードを書いても、検証されないまま積み上がる。**MVP 投入後は、スキーマ変更に明示的な `Migration` とそのテストを必須とする**（運用の詳細は[データモデル定義書](./14_データモデル定義書.md) §8 が規定する）。`fallbackToDestructiveMigration` はどの段階でも足さない——黙ってデータが消えるより、起動時に落ちて気づけるほうを採る。境界を「⑤ ストア公開」から前倒しした経緯は [log_15](./log_15_アーキテクチャ定義書.md) 2026-08-31。

## 3. ドメイン層（`:shared:domain`）

`ItemRepository` / `CategoryRepository` は DAO の薄いラッパー。ステータス遷移（`updateStatusAsInBasket` など）はここに集約されており、同じ状態への更新は早期 return で握りつぶす。**ビジネスルールを足すならここ。**

## 4. UI 層（`:shared:ui`）

### 4.1 画面遷移

Navigation 3。`ui/ReBuyApp.kt` の `NavDisplay` と `entryProvider` に集約し、ルートは `@Serializable sealed interface Screen : NavKey` で定義する。

**画面追加時は同じファイルの 3 か所をそろえる**——`Screen` の `@Serializable data object`、`entryProvider` の `entry<...>`、`screenSavedStateConfiguration` の `subclass(...)`。

**3 つ目の登録を忘れると、その画面にいる状態でプロセス保存が走った瞬間に `SerializationException` になる**（Android も iOS も同じ）。`ScreenSerializationTest` が `sealedSubclasses` と登録内容を突き合わせ、`NavigationStateRestorationTest` が実際に保存・復元を往復させて止める。

backstack は `ui/navigation/NavigationState.kt` がトップレベルルート（ホーム・買い物）ごとに保持し、遷移イベントは `Navigator`（`navigate` / `goBack` / `navigateAsRoot`）が受けて状態を更新する。UI は状態を見るだけ。

### 4.2 画面 Composable

- シグネチャは `(navigator: Navigator, snackbarHostState: SnackbarHostState)` で統一。ViewModel は `koinViewModel<XxxViewModel>()` で画面内から取得する（引数で渡さない）
- 全画面が `ReBuyAppScaffold` を使い、TopAppBar / BottomBar / Snackbar / FAB の構成を共通化している
- セーフエリアは Compose 側で処理する。iOS の `ContentView` は `.ignoresSafeArea()` で画面全体を渡し、インセットは `Scaffold` に任せる。**SwiftUI 側で効かせると余白が二重になる**
- **`when` の `object` 分岐は `is` ではなく等値で書く。** iOS では `is <data object>` が、分岐に `@Composable` 呼び出しを含む `when` の中で一致しない（③ の段 3 で実測）。Android では起きないので Android のテストでは捕まらない

### 4.3 ViewModel

- 複数の `MutableStateFlow` を `combine` して 1 つの `XxxScreenUiState` にまとめ、`stateIn(viewModelScope, SharingStarted.Eagerly, 初期値)` で公開する。Repository の Flow は `init` の `viewModelScope.launch` で collect して private StateFlow に流し込む
- Kotlin 標準の `combine` は 5 引数までなので、6 個をまとめるときはルートの `FlowExt.kt` の自作 `combine` を使う（`ItemEditViewModel` が例）
- ダイアログの開閉フラグも UiState に持たせ、`showXxxDialog()` / `hideXxxDialog()` を ViewModel に生やす
- 派生値（フィルタ済みリストなど）は UiState の `get()` プロパティで計算する（`HomeScreenUiState.inBasketItems` など）
- BottomNavigation を持つ画面の UiState は `BottomNavigationScreenUiState` を実装し、買い物リストのバッジ件数を提供する

### 4.4 リソース

**画面文言と drawable は Compose Resources に置く**（`shared/ui/src/commonMain/composeResources/` の `values/strings.xml` と `drawable/`）。参照側は `io.github.obaya884.rebuy.ui.resources.Res` を import して `stringResource(Res.string.xxx)` / `painterResource(Res.drawable.xxx)` で引く。`Res` は `publicResClass = true` で公開してあるので、`:androidApp` の instrumented テストも同じ文言を引ける。

**`:shared:ui` の Kotlin から Android の `R` を引く場所はもう無いが、`androidResources { enable = true }` は外さない。** Compose Resources は Android では assets 経由で載り、CMP はその配線を `variant.sources.assets` に繋いでいる。無効にすると assets ごと消え、ビルドは緑のまま全画面が落ちる。

**CMP の書式指定は `String.format` ではない。** 解釈されるのは `%1$s` `%1$d` の形だけで、`%s` や `%.2f` は素通しになる（例外も出ない）。

## 5. DI

Koin モジュールを**層ごとに 1 ファイル**置く（`DataModule` / `DomainModule` / `UiModule`）。粒度が「1 依存 1 ファイル」でないのは、Koin では宣言が 1 行で済み、依存ごとにファイルを分けると層の境界が読めなくなるため。新しい依存は該当する層のモジュールに足す。

**各モジュールは `includes` で 1 つ下の層だけを知る**（`uiModule` → `domainModule` → `dataModule` → `platformDataModule`）。アプリが読み込むのは `uiModule` 1 つだけで、残りは Koin が連鎖で解決する。この連なりが Gradle の依存の向きとそのまま対応する。

**起動は `initKoin(appDeclaration)` 1 か所。** プラットフォームで違うのは渡すものだけ（Android は `androidContext(...)`、iOS は無し）。呼び出し元は `ReBuyApplication.onCreate()` と `setupKoin()`。

- `allowOverride(false)`。同じ型の定義が 2 か所に現れたら黙って後勝ちさせず、落として気づく。二重起動のガードも入れない（同じ理由）
- **テストでは `startKoin` を呼ばない。** instrumented は本物の `ReBuyApplication` の上で走るので、二重に起動すると落ちる。差し替えたいときは `loadKoinModules` / `unloadKoinModules` を使う
- **Koin は依存グラフをコンパイル時に検証しない。** 配線ミスは起動時まで分からないので、`KoinModulesTest`（ホスト段）が `verify` でグラフを組み立てられることを固定し、`KoinGraphTest`（instrumented）が依存を 1 つずつしか持たないことを固定している。DI に触れたら両方を回す

## 6. OSS ライセンス表示

AboutLibraries プラグインがビルド時に `shared/ui/src/commonMain/composeResources/files/aboutlibraries.json` を生成し、`LicenseScreen` が `Res.readBytes` で読んで**実行中のプラットフォームのターゲットで絞ってから** `LibrariesContainer` に渡す。依存を追加したらここに自動反映されるので手動更新は不要。

- **生成物だがコミットする**（Room のスキーマと同じ扱い）。依存を足し引きすると diff に出るので、**ライセンス一覧の変化がレビューに乗る**。ビルドのたびに再生成されるため、コミットし忘れは CI の `git diff --exit-code` で止まる
- **収集は `collect { all = true }` ＋ 構成名の名指し**（`androidCompileClasspath` ほか compile/runtime と、iOS 2 ターゲットの `...CompileKlibraries`）。既定の収集は設定名が `CompileClasspath` / `RuntimeClasspath` で終わるものしか見ず、**Kotlin/Native の klib 構成を拾えない**。`all = true` はその名前照合を飛ばす枝で、`filterVariants` の意味が**完全一致から部分一致に変わる**ので、曖昧な語を入れず構成名をフルで書く
- **json は Android と iOS で 1 つを共有し、entry の `targets`（`collect { includeTargets = true }`）で表示時に絞る。** 絞りは `forCurrentPlatform`（`LicenseScreen` と同じパッケージ）で、Android は `android`、iOS は `ios` 接頭辞（実機とシミュレータの 2 ターゲットをまとめる）。**`targets` が空の entry は絞らず表示する**——`configPath` で手足しした entry が黙って消えないように
- 収集が壊れてもビルドとテストは緑のままなので、中身は網で見る: 絞りの規則は `PlatformLibrariesTest`（commonTest）、リソースの中身と Android 側の絞りは `LicenseLibrariesTest`（instrumented）、iOS 側の絞りは `LicenseLibrariesIosTest`（iosTest）
