## 1. 本書の位置づけ

要求定義書の要求（F-XXX・N-XX）を、実装可能な要件に落とし込む。**要求 1 つにつき 1 行で「その機能が何をするか」の規則——起きること・条件・例外——を持つ**のが本書 §5 で、下位文書との分担は次のとおり。

| 文書 | 持つもの |
|---|---|
| 本書 §5 | 要求 ID 単位の挙動の規則（何が起きるか・どの条件で・例外は何か）と、下位文書への参照（トレーサビリティ） |
| [画面定義書](./13_画面定義書.md) | 画面の構成・遷移・操作の入口・文言・見た目（配置・寸法・色） |
| [データモデル定義書](./14_データモデル定義書.md) | データの形・状態遷移・導出（クエリ）・検証則・並び順・Migration 運用 |

挙動を知りたいときは本書を読めば足り、見え方と文言は 13、データの形は 14 に降りる。非機能要求（N-XX）も同じく §5.6 で実現方針と参照先を持つ。

## 2. システム方式

- 全体構成・レイヤ・DI・置き場所の規約は[アーキテクチャ定義書](./15_アーキテクチャ定義書.md)が正（KMP＋Compose Multiplatform、UI → ViewModel → Repository → DAO → Room、Koin、Navigation 3）。テスト戦略は[テスト戦略定義書](./17_テスト戦略定義書.md)が正
- データは端末内の SQLite（Room）で完結する（C-3）。サーバー・アカウントは持たない
- テーマ選択だけは DB ではなく端末内のキーバリュー保存に置く（[14](./14_データモデル定義書.md) §9）

## 5. 要件

要求 ID 単位の挙動の規則。見え方・文言は画面定義書（13）、データ仕様はデータモデル定義書（14）を参照。「登録順」＝ id 昇順（14 §4）。

### 5.1 品目とプール

| 要求ID | 要件 |
|---|---|
| F-101 | 品目の状態は 0 常駐・1 カゴ入り・2 チェック済みの 3 値で、遷移はすべて利用者の操作で起きる（14 §3）。**削除（F-105）以外のどの操作でも品目は消えない**。チェック済みは買い物の終了（F-204）で最終購入日を記録して常駐へ戻る。画面はプール（13 画面 01）が唯一の根で、他はすべてそこから開く（13 §1） |
| F-102 | 登録シート（13 画面 02）。名前だけで確定でき、カテゴリ・行き先は任意（F-103・F-104）。**登録直後の品目はカゴに入れない**（常駐で作る）。「登録」は登録してシートを閉じる。「続けて登録」は登録後に名前だけクリアし、チップの選択を保持したままシートを開いておく。新規登録は一覧の末尾（登録順）に現れる |
| F-103 | `items.categoryId`（0〜1。14 §2）。登録・編集シートのチップ列で選ぶ（13 画面 02・06）。選択中のチップをもう一度タップするとそのチップだけ解除（13 §2）。カテゴリの無い品目の行にはタグを出さない |
| F-104 | `items.destinationId`（0〜1。14 §2）。`destinationId IS NULL` の品目が「どこでも買えるもの」（14 §1）で、行では名乗らない（タグを出さない）。絞り込み・買い物・検索での扱いは F-107・F-203・F-205 |
| F-105 | 品目編集シート（13 画面 06）。名前・カテゴリ・行き先を変更し、「保存」で反映してシートを閉じる（重複判定は自分自身を除く）。削除は物理削除で復元は無い（14 §7）ので、確認ダイアログを挟む。削除後は 01 へ戻る |
| F-106 | 規則（トリム・空不可・同種内の重複不可・30 文字上限・文字種は制限しない）と、UI とデータ層の二重の網の正は 14 §5。入力欄の作法とエラー文言は 13 §2。**重複判定は正規化しない**ので、かな違いの表記は別の名前として登録できる（検索の畳み込み F-205 とは独立） |
| F-107 | 一覧は全品目を登録順で（14 §4・§6）。**カゴ入りも一覧の上には寄せない**（トグルで行が飛ばないように）。絞り込みはカテゴリ 0〜1 個・行き先 0〜1 個の AND で、「すべて」で両方解除、選択中のチップの再タップでそのチップだけ解除（13 §2）。**行き先の絞り込みは厳密**——ある行き先を選ぶとその行き先の品目だけ、「どこでも」は `destinationId IS NULL` の品目だけ。導出は 14 §4 |
| F-108 | `items.lastBoughtAt`（14 §2）。買い物の終了時刻を記録し（F-204）、カゴの出し入れやチェックでは変えない。未購入は null。一覧と編集シートの両方に出す（書式は 13 §2） |
| F-109 | （Could・未詰め）長押しの発見性を初回ヒントなどで補う案。13 画面 01 の残論点から要求に起こした。方式は着手時に決める（[要件バックログ](../案件/22_要件バックログ.md)） |

### 5.2 カゴと買い物

| 要求ID | 要件 |
|---|---|
| F-201 | プールの行タップで状態 0 ↔ 1 のトグル（14 §3）。**チェック済み（2）の行を出すとチェックも失われる**（2 → 0）。カゴの件数は `status` が 1 または 2 の品目数で、01 の下部 CTA のバッジに出す（14 §4）。カゴが 0 件のとき CTA は無効 |
| F-202 | 01 の CTA「買い物を始める」。**カゴに行き先付きの品目が 1 件でもあれば買い物開始シート（13 画面 03）を開き、1 件も無ければシートを挟まず全件モードの買い物（04）へ直行する**——選ぶ相手が無いのに行き先を問わない。全件モードの判定は 14 §4（絞り込みに従わず全件を見る。UI は id ではなく解決済みの行き先の実体で見る）。03 の内訳はカゴ内に品目を持つ行き先だけを手動並び順で並べ、行＝行き先名＋プレビュー（登録順の先頭 2 件の実名）＋件数「n＋m 件」（n＝その行き先のカゴ内件数、m＝どこでも買えるもののカゴ内件数。m が 0 なら「n 件」）。**m が 1 以上のときだけ**脚注で、どこでも買えるものがどの行き先にも一緒に入ることを知らせる。どこでも買えるものを独立した行にはしない。内訳が 1 行でも開く。行タップでその行き先の買い物（04）へ。導出は 14 §4 |
| F-203 | 買い物モード（13 画面 04）。一覧＝カゴ内の「選んだ行き先の品目（登録順）」→ 区切り → どこでも買えるもの（登録順）。全件モードは区切りなしでカゴ全件（14 §4）。行タップで 1 ↔ 2（14 §3）。**チェックしても行の位置は動かさない**。長押し編集は無効。進捗は x／n（x＝一覧中の状態 2 の件数、n＝一覧の総数）。**一覧は買い物中も DB に追随する**ので、05 で足した品目はその場で現れる |
| F-204 | 「買い物を終了する」で一覧中の状態 2 の全件を 0 に戻し、`lastBoughtAt` に終了時刻を記録する（14 §3）。未チェック（1）はカゴに残る。確認ダイアログも待ち時間（スピナー）も置かない（[決定ログ](./log_13_画面定義書.md) 2026-09-01）。**チェック済みが 0 件でも押せる**（何も買わずに終える道）。終了後はプール（01）へ戻る |
| F-205 | 気づいたものを足すシート（13 画面 05）。**どの経路も 1 件でシートは自動で閉じる**。初期表示は状態 0 で「今の行き先 または どこでも」の品目を登録順に（全件モードは状態 0 の全品目を区切りなしで）。検索はトリムした入力の部分一致で全品目を対象にし、**名前と入力の両方を畳んでから比べる**——ひらがなとカタカナ、全角と半角（半角カタカナを含む）、英字の大文字と小文字を同一視する。濁点・半濁点、漢字と読み、踊り字（`ゝゞ`・`ヽヾ`）と `ゟ`・`ヿ` は畳まない（[決定ログ](./log_13_画面定義書.md) 2026-09-06）。導出は 14 §4。当たりは「今の行き先＋どこでも」と「他の行き先」に分け、**追加済みも所属する側の当たりに残して「追加済み」と添える**（タップ無効）。今の行き先・どこでもの品目を選べばカゴ入り（0 → 1）して今の一覧に現れる。**他の行き先の品目はその行き先のカゴに入るだけ**で今の一覧には現れず、スナックバーで知らせる。「この名前で登録する」は検証（F-106）→ 行き先＝今の店・カテゴリなしで登録して即カゴ入り（全件モードは行き先なし）。**畳んで既存が当たっても弾かない**（重複判定は畳まない）。キーボードの確定では登録しない。全件モードは「他の行き先」の枠を使わず、すべて 1 つの枠に出す |
| F-206 | チェックの状態は DB に持つ（14 §3）ので、買い物から離れても・アプリを閉じても残る。**←・システムバックは離脱確認を挟む**（「やめる」で 01 へ。チェックは保持）。05 表示中のバックはシートを閉じるだけ。再開は 01 の「買い物を始める」から（03 で同じ行き先を選ぶ。全件モードは直行）。**iOS でもバーの ← は離脱確認を通す**（13 §6）。プロセスが落ちたときの画面状態の復元は N-02 |
| F-207 | （Could・設計済）候補と勧める順は[検索体験検討](../検討/31_検索体験検討.md) §3・§5（空白・記号を畳む → 前方一致を優先 → 初期表示を最近買ったもの寄りに）。**どれが要るかは実際の空振りを FB で集めてから決める**（同 §7）。決まった案はここに規則として書き、見え方は 13 画面 05 へ |

### 5.6 非機能

要求定義書 §6.6 の N-XX ごとに、どこで何によって成り立たせているか。手段・数値・網の実体は参照先が持つ。

| 要求ID | 要件 |
|---|---|
| N-01 | スキーマ変更には明示的な Migration とそのテストを必須とし、`fallbackToDestructiveMigration` は使わない。移行できない DB は起動時に落とす（14 §8、15 §2.3）。網が届くのは下げ方向までで、上げ方向は T-34 |
| N-02 | チェックの状態は DB に持ち（14 §3）、画面の状態はプロセス保存で復元する（15 §4.1） |
| N-03 | データは端末内の SQLite と端末内キーバリューに置く（§2）。INTERNET 権限も通信する依存も持たない。OS のバックアップから外す設定はしない（Android の `allowBackup`、iOS は DB を NSDocumentDirectory の下に置く。15 §2.2） |
| N-04 | minSdk 31・iOS 26（要求定義書 §9）。iOS は iPhone のみで向きは固定しない（15 §7）。タブレットは要求定義書 §7 のスコープ外 |
| N-05 | 選択中のチップは先頭に ✓、カゴ入り行はトグルの ✓ を持つ（13 §2・§5） |
| N-06 | 選択面 `accent-soft` を上下の条件で挟んで決め、基本文字 `ink` が 4.5:1 を割らない範囲に置く（13 §5）。補助文字 `muted` の扱いは FB-17 |
| N-07 | 文言は Compose Resources の `strings.xml` に置く（15 §4.4）。対応言語は日本語のみ（要求定義書 §3・§7） |
| N-08 | AboutLibraries が生成する一覧をコミットし、実行中のプラットフォームで絞って表示する（15 §6）。同梱フォントは手で一覧に足す（13 §5） |
| N-09 | 署名まわりの設定は xcconfig に置き、pre-commit と CI の検査で止める（16 §1.4）。コミットしない対象の全量は `.gitignore`・`.claude/settings.json` の deny・検査スクリプトの 3 点セットが正（CLAUDE.md「このリポジトリは public」）。CI のログ・成果物の側は ⑤ で N-10・N-11 とあわせて定める |
| N-10 | ⑤ のリリース整備で定める（要件バックログ）。手段の候補は要求定義書の決定ログ 2026-10-02 |
| N-11 | 同上 |
