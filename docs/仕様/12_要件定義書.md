## 1. 本書の位置づけ

要求定義書の要求（F-XXX）を、実装可能な要件（方式・画面・データ）に落とし込む。画面の詳細仕様は画面定義書に、データ構造とその規律はデータモデル定義書に分割し、本書は全体方針・機能要件（要求 ID 単位の実現方針）・トレーサビリティを担う。

## 2. システム方式

- 全体構成・レイヤ・DI・置き場所の規約は[アーキテクチャ定義書](./15_アーキテクチャ定義書.md)が正（KMP＋Compose Multiplatform、UI → ViewModel → Repository → DAO → Room、Koin、Navigation 3）。テスト戦略は[テスト戦略定義書](./17_テスト戦略定義書.md)が正
- データは端末内の SQLite（Room）で完結する（C-3）。サーバー・アカウントは持たない
- テーマ選択だけは DB ではなく端末内のキーバリュー保存に置く（[14](./14_データモデル定義書.md) §9）

## 3. 開発の現況

④ の MVP 実装フェーズ。要求は F-002〜F-013 の全部が Must ＝ MVP（要求定義書 §6）で、**2026-09-01 にすべて実装を終えた**（[完了記録](../案件/closed_22_要件バックログ.md)）。既存 6 画面は新画面群で置き換え済み。**残る ④ の完了条件は「オーナーが数週間使い続けている・FB が回っている」**で、そこから出た要求は[要件バックログ](../案件/22_要件バックログ.md)が受ける。

## 4. 画面一覧

画面の一覧・遷移・番号（01〜09b）は[画面定義書](./13_画面定義書.md) §1 が正。タブは無く、プール（01）が唯一の根。

## 5. 機能要件

要求 ID 単位の実現方針。UI 詳細は画面定義書（13）、データ仕様はデータモデル定義書（14）を参照。

### 5.1 土台

| 要求ID | 要件 |
|---|---|
| F-002 | destinations テーブルを新設し、items に destinationId（FK・ON DELETE SET NULL）を足す。categories・destinations に手動並び順 sortOrder を持たせる。スキーマは 14 §2、並び順規則は 14 §6。④ の実装中は Migration を書かず version を上げて入れ直す（14 §8） |
| F-003 | 名前の検証（トリム後の空不可・同種内の重複不可・30 文字上限）を UI とデータ層の二重の網で行う。Repository が保存前にトリムと検証を行い違反は結果型で返し、DB の UNIQUE インデックスを最後の砦にする。規則の正は 14 §5、入力欄の挙動とエラー文言は 13 §2 |
| F-004 | 13 §5 の配色トークン（3 パレット × 明暗）とタイポグラフィを Compose のテーマとして実装する。テーマ画面（13 画面 08）のタップで即時反映し、選択は端末内キーバリューに保存（14 §9）。明暗は OS 設定に追従し、アプリ内に切り替えは置かない |

### 5.2 画面

| 要求ID | 要件 |
|---|---|
| F-005 | プール画面（13 画面 01）。一覧は全品目の登録順（導出は 14 §4）、行タップで状態 0 ↔ 1 のトグル（14 §3）、長押しで品目編集シート。絞り込みチップはカテゴリ・行き先の AND（「どこでも」は destinationId IS NULL） |
| F-006 | 登録シート（13 画面 02・02b）。名前だけで確定でき、カテゴリ・行き先はチップで任意選択。「＋ 新しいカテゴリ／行き先」ダイアログを内包し、「続けて登録」は名前だけクリアして開いたまま |
| F-007 | 品目編集シート（13 画面 06）。名前・カテゴリ・行き先の変更と削除（物理削除。14 §7） |
| F-008 | 買い物開始シート（13 画面 03）。カゴを行き先別に内訳表示（導出は 14 §4）し、行タップでその行き先の買い物モードへ。行き先付きが無ければ全件モードの 1 行 |
| F-009 | 買い物モード（13 画面 04）。一覧＝選んだ行き先の品目 ∪ どこでも買えるもの（14 §4）。行タップで状態 1 ↔ 2、「買い物を終了する」で状態 2 の全件を 0 に戻し lastBoughtAt を記録（14 §3）。←・システムバックは離脱確認、チェックは DB に残り再入場で続きから |
| F-010 | 気づいたものを足すシート（13 画面 05）。検索は全品目の単純部分一致（14 §4）。他の行き先のヒットはその行き先のカゴにだけ入りスナックバーで通知。「＋ この名前で登録する」で行き先＝今の店・即カゴ入りの新規登録。どの経路も 1 件で自動クローズ |
| F-011 | 設定画面（13 画面 07）。カテゴリの管理、テーマ（右端に現在のテーマ名）、ライセンス（既存 AboutLibraries 画面を流用）への導線とバージョン表示 |
| F-012 | カテゴリの管理画面（13 画面 09・09b）。sortOrder のドラッグ並び替え、その場の追加ダイアログ、長押しで編集シート、削除は SET NULL で品目を残す（14 §6・§7） |
| F-013 | 行き先の管理（13 画面 09・09b）。**画面そのものは F-012 が作った**（09 は同型の 2 画面なので、向きで切り替わる 1 つの実装）。ここで足すのは設定（07）の「行き先の管理」の行と、行き先向きの自動化網。削除確認では「どこでも買えるもの」になる旨を件数付きで示す |
