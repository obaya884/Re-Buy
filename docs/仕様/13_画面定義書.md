## 2. 操作の共通作法

- **行タップ＝最頻で取り消し可能な操作**。プールではカゴ出し入れ、モードではチェックの付け外し
- **行の長押し＝編集シート**。01・09 で共通。**04（買い物モード）では長押し編集は無効**
- FAB は置かない。品目の登録はアプリバーの＋から
- 削除は常に編集シート（06・09b）の中に置き、確認ダイアログで影響を件数提示する
- **確認ダイアログのボタンは Material の既定**——打ち消しが左・確定が右で、どちらも素の文字（色は別。削除の確定には危険色を当てる）。**例外は 04 の離脱確認だけ**（画面 04）
- **「システムバック」は OS が用意する戻る操作を指す。** Android は戻るボタンとジェスチャー、**iOS は画面の端から内側へのスワイプ**。どちらも同じ条項に従う。**iOS では OS の版によって使えないことがある**（[T-62](../案件/23_技術改善バックログ.md#t-62)）が、**使えるときに条項から外れてよいわけではない**
- シートはスクリム・グリップ付きのボトムシート。スクリムタップ・下スワイプ・システムバックで閉じる（保存されていない入力は破棄）
- **シートは開いた時点でキーボードを出さない**（入力欄に自動フォーカスしない）。シートのスライドインとキーボードが同時に始まり、キーボードが出切った時点でシートがその高さぶん持ち上がるため、**画面が 2 回動いて見える**
- ダイアログ表示中のシステムバックはダイアログだけを閉じる
- スナックバーは「画面に変化が見えない操作」の完了通知にだけ使う（現時点では 05 の思い出しの追加のみ）
- **選択中のチップをもう一度タップするとそのチップだけ解除**。絞り込み（01）でも、登録・編集の選択（02・06・09b）でも同じ
- **選択中のチップは先頭に ✓ を出す。** 絞り込み（01）でも、登録・編集の選択（02・06）でも同じ。面の色だけで選択を示さない——選択面と地の差は**いちばん狭いところで 1.02:1**（ほぼ同色）で、パレットと明暗で効き方も変わる。**色に頼らない手がかりを 1 つ持たせる**（FB-07）
- 日付表示は一覧では「前回 M/D」（未購入は「前回 —」）、編集シートでは「最終購入日: YYYY-MM-DD」

### 名前入力の共通仕様

品目・カテゴリ・行き先の名前入力欄（02・02b・06・09b・05 の検索欄からの登録）に共通。検証則の正は [14](./14_データモデル定義書.md) §5。

- 31 文字目以降は入力できない（打ち切り）
- 確定操作（登録・作成・保存）時にトリムして検証し、エラーは入力欄の下に赤字で出す。シート・ダイアログは閉じない
- エラー文言: 空は「名前を入力してください」、重複は「同じ名前がすでにあります」、上限超えは「30 文字以内で入力してください」
- **エラーは必ず文言を持つ。** 打ち切りがあるので上限超えは通常起きないが、**起きない想定のエラーにも文言を置く**——文言の無いエラーは、赤枠だけが出て理由が分からない状態になる。今後足すエラーも同じ

## 3. UI に出す語彙

「登録＝品目を作る」「追加＝買うものに入れる」の書き分けが軸。実装語彙（品目・アイテム・カゴ・プール・モード）は UI 文言に出さない。

| 概念 | UI に出す語 | UI に出さない実装語彙 |
|---|---|---|
| 品目 1 つ | 名詞を出さない（動詞・実名・「もの」で語る） | 品目・Item・アイテム |
| 品目を新しく作る | 登録 | insert |
| 買うものに入れる | 追加・追加済み・未追加 | カゴ・basket・InBasket |
| 常駐する全品目の集合 | 名詞を出さない（「全 n 件」） | プール・pool |
| 店でチェックする状態 | 買い物中・チェック | 買い物モード・mode |
| 品目の分類タグ | カテゴリ | Category |
| 買う店 | 行き先 | destination |
| 行き先のない品目 | どこでも買えるもの | 行き先なし・null |
| 行き先を選ばない買い物 | 名詞を出さない（アプリバーは「買い物中」） | 全件モード |

**「どこでも買えるもの」は場面で長さを変える。** 文中（04・05 の区切りラベル、09b の削除確認）は正式名、**幅が限られるチップ（01）だけ「どこでも」と短くする**。同じ概念が 2 通りで出るが、短縮形はチップの中でしか使わない（FB-11）。

## 4. 画面定義

### 01 プール

唯一の常駐画面。全品目の一覧と管理、買い物の起点。挙動は F-107（一覧・絞り込み）・F-201（カゴ出し入れ）・F-202（買い物の開始）。

- **アプリバー**: ブランド名「Re-Buy」＋総数「全 n 件」。右に＋（→ 02）と⚙（→ 07）
- **絞り込みチップ列**: 先頭「すべて」、続いてカテゴリ（手動並び順）、行き先（手動並び順）、末尾「🏬 どこでも」。**カテゴリ群と行き先群の間に縦の細線を挟む**——1 行に連なると群の境が見えず、各群から 1 つずつ選べることが伝わらない（FB-08）。**カテゴリが 1 つも無いときは線を出さない**（仕切る相手が無い）。選択の作法は §2
- **一覧**: 行＝名前＋カテゴリタグ＋行き先タグ＋「前回 M/D」＋トグル。カゴ入りは行の色（`accent-soft`）とトグルの ✓ で示す
- **カテゴリと行き先には絵文字を前置する**（カテゴリ 🏷・行き先 🏬）。**表示のときに付けるもので、名前の一部ではない。** 片方だけに付けると対称が崩れるので両方に付ける（FB-13）。出るのは行のタグと絞り込みチップで、行き先はこれに加えて 05 の「他の行き先から」の行
- **行タップ**: カゴ出し入れ（F-201）
- **行の長押し**: 06 を開く
- **下部 CTA**: 「買い物を始める」＋カゴ件数バッジ。03 を開くか 04 へ直行するかは F-202（FB-04）。行き先を使わない人はこの分岐で 03 を一度も見ない。**カゴの中身はこの一覧で見えている**ので、確認の場を飛ばすことにもならない
- **空状態**（品目 0 件）: 「まだ何も登録されていません」＋「右上の ＋ から登録できます」
- **絞り込み結果 0 件**: 「この条件のものはありません」
- 長押しの発見性を補う案は F-109（Could）

### 02 登録シート

挙動は F-102（登録・続けて登録）・F-103・F-104（任意の選択）。

- タイトル「新しく登録」。名前入力欄（プレースホルダ「名前」）＋「カテゴリ（任意）」「行き先（任意）」のチップ列。チップは各 0〜1 個選択、末尾に「＋ 新しいカテゴリ」「＋ 新しい行き先」（→ 02b）
- ボタンは「登録」と「続けて登録」の 2 つ。検証エラーの出し方は §2

### 02b 新しいカテゴリ／行き先ダイアログ

挙動は F-303。

- タイトル「新しいカテゴリ」または「新しい行き先」。名前入力欄だけの小ダイアログ。「作成」「キャンセル」

### 03 買い物開始シート

出発前ビュー。カゴの中身を行き先別に確認し、行き先を選んでモードに入る。開く条件・内訳の中身・脚注の条件は F-202。

- タイトル「今日はどこへ？」＋補足「行き先を選ぶと、買い物が始まります」
- **内訳行**: 行＝行き先名＋プレビュー＋件数。プレビューは実名を「・」で繋ぐ（「牛乳・食パン」。「など」は付けない）。件数は「n＋m 件」または「n 件」
- **行タップ**: その行き先の 04 へ（シートは閉じる）
- **脚注**: 内訳の下に淡色で「＋m 件はどこでも買えるもの。どの行き先にも一緒に入ります」（FB-09。出す条件は F-202）

### 04 買い物モード

店内のチェック画面。挙動は F-203（一覧・チェック）・F-204（終了）・F-206（離脱と再開）。

- **アプリバー**: ←＋タイトル「◯◯で買い物中」（全件モードは「買い物中」）＋進捗「x / n」
- **一覧**: 選んだ行き先の品目 → 区切りラベル「どこでも買えるもの」→ どこでも買えるもの。全件モードは区切りなしの単一リスト。一覧の末尾に破線行「＋ 気づいたものを足す」（→ 05）
- **行タップ**: チェックの付け外し。チェック済みは ✓＋取り消し線で示す
- **下部 CTA「買い物を終了する」**: 押すと 01 へ戻る（F-204）
- **←・システムバック**: 確認ダイアログ「買い物を途中でやめますか？」＋「チェックした内容は残ります。あとから再開できます。」＋「やめる」（左・素の文字）「続ける」（右・**アクセント色の塗りで強調**。下部 CTA と同じ面）。**確認ダイアログでここだけが §2 の既定から外れる**（FB-12）

### 05 気づいたものを足すシート

モード中の割り込み追加。初期表示・検索の畳み方・当たりの分け方・追加と登録の挙動は F-205。

- タイトル「気づいたものを足す」＋検索欄（プレースホルダ「名前で探す…」）
- **セクション**は上から「未追加のものから選ぶ」（中に区切り「どこでも買えるもの」）→「他の行き先から」→「＋ この名前で登録する」ボタン（固定文言。入力が空白のみでない間、常に末尾に表示）。空のセクションは見出しごと出さない
- **「他の行き先から」の行には行き先名（🏬 ◯◯）を添える**——複数の店の品目が混ざるので、名前だけではどこのカゴに入るか分からない
- 追加済みの当たりは「追加済み」の表示（タップ無効）で出す
- 他の行き先へ入れたときのスナックバー: 「◯◯に追加しました」（◯◯＝行き先名）
- 検索の畳み方の決定（FB-10）と踊り字を畳まない判断は[決定ログ](./log_13_画面定義書.md) 2026-09-06

### 06 品目編集シート

挙動は F-105。

- 01 の行の長押しで開く。タイトル＝品目名。02 と同じ型で、名前入力欄＋カテゴリ・行き先のチップ列（「なし」チップと「＋ 新しい〜」を含む）＋「最終購入日: YYYY-MM-DD」（未購入は「最終購入日: —」）
- ボタンは「保存」と「「◯◯」を削除…」
- 削除の確認ダイアログ: 「「◯◯」を削除しますか？」＋「削除すると元に戻せません。」＋「削除する」「キャンセル」

### 07 設定

挙動は F-402。利用規約・プライバシーポリシー・問い合わせの行は F-403（Should）が入るまで出さない。

- 行: 「カテゴリの管理」「行き先の管理」「テーマ」（現在のテーマ名を右端に表示）「ライセンス」。**画面の下端に固定**してバージョン「Re-Buy x.y.z」

### 08 テーマ

挙動は F-401。

- 「若葉」「藍」「柿」の 3 択。行＝色見本＋名前＋選択中の ✓。保存ボタンは無い

### 09 カテゴリの管理／行き先の管理

同型の 2 画面。挙動は F-301・F-302。

- **一覧**: 行＝ドラッグハンドル ≡＋名前。行の高さは一定で、**入りきらない名前は末尾を「…」で省略**（全文は 09b で見る）
- **末尾の破線行**「＋ カテゴリを追加」「＋ 行き先を追加」: 02b を開く
- **行の長押し**: 09b を開く
- **空状態**: 破線行だけを出す

### 09b カテゴリ／行き先の編集シート

挙動は F-301・F-302（名前変更）・F-304（削除）。

- 06 と同じ型。タイトル＝現在の名前、名前入力欄＋「保存」
- **「「◯◯」を削除…」**: 確認ダイアログの文言は、行き先が「「◯◯」を削除しますか？」＋「紐づく n 件は「どこでも買えるもの」になります。」、カテゴリが「紐づく n 件はカテゴリなしになります。」（n＝0 のときは「紐づくものはありません。」）。「削除する」「キャンセル」

## 5. デザイン

素の Material から離れ、「台所のメモ」寄りの面構えにする。

- **タイポグラフィ**: 見出し・CTA は丸ゴシック（Zen Maru Gothic の Bold 1 ウェイトを同梱。約 3.8MB）、本文は OS 既定のゴシックに任せる。**本文用のフォントは同梱しない**（配布サイズを倍にするだけの効きが無い）。**「見出し」に当たるのは画面・シート・ダイアログの見出しで、CTA はボタンの文字**。どの書式が引かれるかは Material の部品側が決めるので、**新しい部品を使うときは引かれる書式が丸ゴシック側かを確かめる**
- **形状**: 角丸を大きめに取る（行 13dp・CTA 15dp・シート上部 22dp を目安）
- **一覧の行**: 高さは最低 64dp（01・04・05・09 で共通）。**中身が 1 段でも 2 段でも同じ高さにする**——2 段の 01 と 1 段の 04 を行き来すると揃っていないように見え、05 は行き先の有無で 1 画面の中でも割れる（FB-06）。64dp は 2 段（24 ＋ 16）に上下 12dp を足した値なので、**いちばん高い行に他を合わせている**。**末尾の破線の行（04・09 の「＋ ◯◯」）も同じ高さ**——同じ一覧に混ざるので、行だけ揃えても末尾で段差が出る
- **下部 CTA**（01「買い物を始める」・04「買い物を終了する」）: 高さ 56dp（Material のボタンのサイズ段 32 / 40 / **56** / 96 / 136 の中間）、周囲 16dp、画面幅いっぱい。**既定の 40dp は、幅が画面いっぱいに伸びる CTA としては低く見える**（FB-14）。**ダイアログやシートのボタンは既定のまま**で、揃えるのは下部 CTA だけ
- **チップ列の群の仕切り**（01）: `line` の縦線を 24dp。**チップ（32dp）より低くする**——同じ高さだと列を断ち切って見え、2 つの列が並んでいるように読める
- **数字**: 件数・日付・進捗は等幅数字（tabular-nums）
- **アプリバーのアイコン**: 的は 28dp（Material 既定の 24dp では小さいという指摘。FB-03）。**当たり判定と押した跡（リップル）は Material の既定（48dp / 40dp）のまま**——`IconButton` に大きさを渡しても当たり判定は変わらず、リップルだけが太る
- **アプリバーに添える数**（01 の「全 n 件」・04 の進捗「x / n」）: 右を 16dp 空ける。**01 は右隣が ＋ なので、密着しているとどこからがボタンか見えない**（04 はバーの右端）

### 配色トークン

3 パレット × 明暗。パレットで変わるのは面と アクセント系だけで、文字色・危険色は共通。

**地は 1 段。** アプリバーも本文も同じ `page` で塗り、その上に `card` が浮く。**アプリバーだけ別の面にしない**——境目の線が出て、画面が 2 枚に割れて見える。

| muted | 補助文字 | #6E7767 | #9BA492 |

| scrim | シート背後の幕 | rgba(30,36,28,0.45) | rgba(5,8,4,0.55) |

| card | 行・カード | #FFFFFF | #2A3127 | #FFFFFF | #262B33 | #FFFFFF | #302921 |

| 向き | 条件 | 意味 |
|---|---|---|
| 下限 | 地（`page`）とも隣の行（`card`）とも、**その配色で `card` が `page` に浮く比より大きく離れる** | 選んだものが埋もれない |
| 上限 | 選択面の上の基本文字（`ink`）が **[WCAG AA](https://www.w3.org/TR/WCAG21/#contrast-minimum) の 4.5:1 を割らない** | 濃くしすぎて行の文字が読めなくならない |

**[WCAG 1.4.11](https://www.w3.org/TR/WCAG21/#non-text-contrast) の 3:1 は狙わない**——色に頼らない手がかりを別に持っているため（チップの ✓ は FB-07、カゴ入り行はトグルの ✓）。

**比べる相手は役目で違う。** 選択チップは地（`page`）の上に載るが、**カゴ入り行が並ぶ相手は地ではなく隣の白い行（`card`）**。片方だけを見て濃さを決めない。

**補助文字（`muted`）を選択面の上に置く組み合わせは、この規則の対象外**——カゴ入り行の「前回 M/D」とタグがこれに当たり、AA を割っている。配色トークンの組み合わせ全体に下限を敷く話として[FB-17](../案件/21_FB台帳.md#fb-17)が持つ。

## 6. iOS の外枠

**外枠だけをネイティブ（SwiftUI）で持ち、中身は Compose で描く**（[要求定義書](./11_要求定義書.md) §9）。ここでいう外枠は**ナビゲーションバー 1 つだけ**——§1 のとおりタブは無いので、`NavigationStack` が 1 本あればよい。**Android の見え方はこの節で変わらない。**

| 部品 | どちらが持つか | 理由 |
|---|---|---|
| ナビゲーションバー（見出し・添える数・アクション・戻る） | **SwiftUI** | ここを OS の部品にすると、iOS 26 のシステムが Liquid Glass を描く |
| 画面の中身 | Compose | 両 OS で 1 実装。§4 の画面定義がそのまま効く |
| シート・ダイアログ（02・02b・03・05・06・09b） | Compose | iOS の `.sheet` に出すと 6 つが二重実装になり、C-4（単純さ）と釣り合わない。**スクリムはバーまで掛かる**ので SwiftUI 側で重ね当てる対処は要らない（実測）。**後から個別に出すことはできる** |
| 下部 CTA（01・04） | Compose | 有効・無効と件数が Compose 側の状態に紐づいており、SwiftUI へ出すと配線が増える |

- **バーに出すものは Kotlin が決め、SwiftUI は描くだけ。** 見出し・添える数（01 の「全 n 件」・04 の「x / n」）・アクション（01 の ＋ と ⚙）・戻るの有無は画面ごとに違うので、**Kotlin が 1 つの状態として渡す**。**iOS では Compose 側はバーを描かない**——両方が描くと見出しが縦に 2 つ並ぶ
- **アイコンは種類だけを渡し、描く側が対応表を持つ。** Android は Material のアイコン、iOS は SF Symbols。**色は ARGB で渡す**——配色トークンの正は §5 の 1 か所に保つ
- **中身はバーの下まで流す。** バーの背後をコンテンツが通らないと**屈折する対象が無く、ただの半透明の板に見える**。スクロールする一覧は上端の余白を内側に持ち、外枠からは受け取らない
- **背後を通る画面では、行の文字が見出しの横や上に重なって見える。これは許容する**（[決定ログ](./log_13_画面定義書.md) 2026-09-13）。地を出して切り分けることはしない
- **ただし、背後を通るのは一覧が上端まで届く画面だけ**（04・09・ライセンス）。**01 はチップ列が一覧とバーの間にいる**ので一覧がバーまで届かず、07・08 はスクロールしないので、背後を通るのは地になる。**01 のチップ列を一覧と一緒にスクロールさせることはしない**——Android の見え方も変わる
- **下部 CTA はホームインジケータを避ける。** 画面下端の横棒に重なるため。**Android のジェスチャーナビゲーションと同じ扱い**で、避けるのは Compose 側（`WindowInsets`）
- **04 の戻るは、iOS でも離脱確認を通す。** バーの ← は「1 つ戻る」ではなく**画面が決めた動作**を呼ぶ。04 はそこに確認ダイアログを繋ぐ（F-206）。**ここを素通りさせると、店で手を動かしている最中に黙って 01 へ戻る**——チェック自体は残る（F-206）が、買い物が中断される
- **§5 の「アプリバーだけ別の面にしない」は iOS でもそのまま効く。** バー自体は地を持たず本文と地続きで、**Liquid Glass が付くのは部品だけ**。§5 と緊張しないので §6 が上書きすることはしない
- **ガラスの地を付けるのは押せるものだけ。** 添える数（01 の「全 n 件」・04 の「x / n」）は**地の上にそのまま置く**——ガラスのカプセルは操作できるものの意匠なので、押せないものを同じ入れ物に入れるとボタンに見える。**並びは変えない**（数はアクションの左のまま）
- **見出しは inline に固定し、寄せ方は OS に任せる。** 大見出し（large title）は使わない——折りたたみが `UIScrollView` と連動する仕掛けで、中身が Compose である限り動く相手がおらず伸びたまま残る。**inline でも画面によって中央寄りと左寄りが変わる**（右の部品が広いと中央に置けない）が、OS の判断に委ねる。**スクロール端の効果**（iOS 26 でバーの縁がスクロールに応じて変わるもの）が付かないのも同じ理由で、**外枠の持ち方をどう変えても解けない**
- **遷移中、バーは中身と一緒には動かない。** 中身は Compose の `NavDisplay` がスライドさせ、バーは SwiftUI が別に差し替えるので、**バーだけが遷移の開始時点で切り替わる**。これも外枠の持ち方によらない構造上の帰結（[決定ログ](./log_13_画面定義書.md) 2026-09-13）
- **端からのスワイプは iOS のシステムバックとして扱う**（§2）。**確実な戻り道はバーの ← だけ**——端スワイプは OS の版によって使えないことがある（[T-62](../案件/23_技術改善バックログ.md#t-62)）。ただし**使えるときは §2・§4 の条項がそのまま当てはまる**。とくに **04 は離脱確認を必ず通す**
